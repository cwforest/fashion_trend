LLM 활용 패션 트렌드 조기 탐지 및 사입 후보 추천 시스템

> **현재 상태: 수집 계층까지 구현.** 탐지·모형은 아직 없다.

## 무엇을 만드는가

에이블리에서 여성 의류를 팔고 동대문에서 직접 사입하는 소규모 셀러를 위해,
**매주 한 장짜리 사입 검토표**를 내놓는 시스템.

트렌드 대시보드가 아니다. 이미 뜬 것을 보여주는 건 늦다.
중심은 **아직 크지 않은데 빠르게 가속 중인 것**이고, 그 판단을 놓을 맥락으로
주력 품목의 현재 수요와 꺾이는 품목의 경고를 같이 낸다 (→ [§5-6](docs/ARCHITECTURE.md)).

```
주력      늘 떼오는 품목 — 평년 곡선 대비 지금 위치, 품목 안 구성 변화
뜨는 것    작지만 가속 중인 후보 TOP 10          ★ 이 프로젝트의 본체
꺾이는 것  컸는데 식는 것 — 신규 사입 중단·재고 소진 경보
```

```
LLM 웹 검색 ─┐
             ├─► 키워드 정규화 ─► 쇼핑인사이트 조회 ─► 통계 탐지 ─► 주간 한 장
검색광고 연관어 ┘   속성 분류        10~20대 여성        계절성 제거     (세 칸)
```

## 중심 연구 질문

> 계절성과 관성을 걷어낸 뒤에도 남는 상승 신호가, 단순 규칙보다 더 일찍·더 정확하게
> 사입할 만한 품목을 집어내는가?

소급 백테스트(롤링 오리진)로 **계절 나이브**·**단순 상승률 규칙**과 겨룬다.
지표는 Lead Time, Precision@10, False Alarm Rate.

> 발굴 경로 두 가지(LLM 웹검색 / 검색광고 연관어)는 **겨루지 않고 역할을 나눈다** —
> 초기 설계에서는 이 둘을 경쟁시키는 것이 중심 질문이었으나 철회했다. 이유는
> [ARCHITECTURE §2-3](docs/ARCHITECTURE.md), 경위는 [PROGRESS 정정 이력](docs/PROGRESS.md).

## 데이터 소스

**쓰는 것**

| 소스 | 얻는 것 | 한도 |
|---|---|---|
| 쇼핑인사이트 (API HUB) | 쇼핑 클릭 추이, 성별·연령·기기 분해 | 월 50,000건 |
| 검색광고 키워드도구 | 연관어 발굴 + 월간 검색수 **절대값** | 별도 체계 |
| 검색어 트렌드 (API HUB) | 검색 관심도 — 쇼핑 클릭과의 괴리 측정용 | 월 50,000건 |
| 문서검색 (API HUB) | 블로그·카페·뉴스 — 담론 선행 신호 | 합계 월 775,000건 |
| 신상마켓 | 동대문 도매 신상 — **최상류 선행 신호** | 수기 관찰 |

**못 쓰는 것**

- **네이버 쇼핑 검색 API** — 2026-07-31 완전 종료, 대체 없음.
  상품 단위 데이터의 공식 경로가 사라져서, 분석 단위가 "상품"이 아니라 **"검색어 → 속성"** 이다.
- **에이블리 셀러 API** — 존재하지 않음. 판매자센터 로그인 뒤에만 확인 가능

### 인증 — 두 체계가 별개다

```
① NAVER API HUB                    ② 네이버 검색광고 API
   네이버클라우드 계정                  네이버 검색광고 계정
   naverapihub.apigw.ntruss.com       api.searchad.naver.com
   X-NCP-APIGW-API-KEY-ID / -KEY      X-API-KEY / X-CUSTOMER / X-Signature
```

둘 다 발급받아야 한다. 광고를 집행하지 않아도 ②는 신청 가능하다.

## 단계

- **Phase 0** — 키 발급 ✅, 셀러 데이터 확인 *(미팅 대기)*
- **Phase 1** — 수집 + 앵커 체이닝 + 조기 탐지 + 백테스트 ★본체
- **Phase 2** — LLM 속성 레이어 (키워드 → 실루엣·소재·컬러)
- **Phase 3** — 판매 데이터 결합, 사입 수량 최적화 *(데이터 확보 시에만)*

## 알려진 가장 큰 리스크

**네이버 신호가 에이블리 고객을 대변하는가?** 10~20대 여성은 탐색을 네이버가 아니라
에이블리 앱·인스타·틱톡에서 한다. 세그먼트 필터·정답지 대조·속성별 상관 측정으로 대응하지만,
셋 다 검증이 필요한 가설이지 해결책이 아니다. 자세한 내용은 [PROGRESS.md](docs/PROGRESS.md) 의 "가장 큰 미해결 리스크".
