## 0. 한 줄

키워드 `i` 의 **점유율 로그 변화율**을 4주 앞으로 예측한다.
과거 자기 자신의 변화율(자기회귀 항)과 계절, 그리고 속성군의 움직임을 설명변수로 둔다.

```
base(i,t) = mean( share(i, t-3 … t)   )      직전 4주 — t 까지만 보므로 누수 없음
fut (i,t) = mean( share(i, t+1 … t+4) )      다음 4주
y   (i,t) = log( fut / base )
```

> **한 점 대 한 점이 아니라 4주 평균끼리다** (2026-10-27 변경).
> 원안은 `log( s(t+4) / s(t) )` 였으나 기준점 한 주가 검열되면 행이 통째로 죽고,
> 검열이 아니어도 고유값비 0.45 인 계단 위의 한 점이라 불안정했다. 근거는 §4-5.
> 비교를 위해 원안도 백테스트 항목으로 남긴다.

`share` 는 `ratio ÷ 앵커평균 ÷ 분야지수` (§7-0 3단계). 원지수가 아니다 —
플랫폼 전체가 1년에 −43.5% 빠졌으므로 원지수로 자기회귀를 돌리면
**모든 키워드가 똑같이 하락하는 공통 추세**만 학습한다.

## 1. 왜 키워드별 ARIMA 가 아니라 패널인가

처음에 떠올리는 구조는 키워드마다 ARIMA 하나씩이다. 쓸 수 없다.

| | 키워드별 ARIMA | 패널 (전역) |
|---|---|---|
| 신규 키워드 | **불가** — 과거 10~30주로 계절항(52주)을 못 추정한다 | 다른 키워드에서 배운 계수를 그대로 쓴다 |
| 결측 | 키워드마다 다른 구멍. 보간 가정이 1,700개 | 결측 자체를 변수로 (`obs_rate_8w`) |
| 모형 수 | 1,700개 적합·검증·재학습 | 1개 |
| 속성 공유 | 불가 | 버건디가디건이 **버건디군 전체**의 움직임을 입력으로 받는다 |

결정적인 건 첫 줄이다. **조기 탐지의 대상이 바로 과거가 짧은 키워드**인데,
키워드별 모형은 정의상 그 키워드에 못 쓴다. 목적과 구조가 어긋난다.

> **고정효과(키워드 더미)도 같은 이유로 안 쓴다.** `u_i` 를 넣으면 과거가 있는
> 키워드에는 잘 맞지만 신규 키워드에는 넣을 값이 없다. 키워드 고유의 성질은
> 더미 대신 **속성 열**(`item` · `color` · `material` …)이 대신 짊어진다.
> 이게 §7-2 에서 속성을 one-hot 이 아니라 범주형 + 군집계로 둔 이유와 같은 뿌리다.

## 2. 사다리 — 네 단계로 올라간다

한 번에 LightGBM 으로 가지 않는다. **각 칸이 아랫칸을 이겨야 올라간다.**
못 이기면 모형이 아니라 데이터가 문제라는 뜻이고, 그걸 아는 것이 이 프로젝트의 산출물이다.

| | 모형 | 무엇을 쓰나 | 역할 |
|---|---|---|---|
| **M0** | 계절 나이브 | `ŷ = log( share(t+4-52) / share(t-52) )` — 작년 같은 구간의 변화율 | 최저 기준선. 이걸 못 이기면 전부 무의미 |
| **M1** | 규칙 점수 | 현행 `detect.py` — 상승률·가속도·지속성 가중합 | 지금 있는 것. 학습 없음 |
| **M2** | **패널 선형 AR** | 시차 로그 변화율 + 계절 + 수준 | **자기회귀의 본체.** 계수를 눈으로 읽을 수 있다 |
| **M3** | 패널 AR + 속성 + **격자** (LightGBM) | M2 + 속성 범주 + 속성군 집계 + 격자 열(§3-4) | 비선형·상호작용. **cold start 는 여기서만 된다** |
| **M4** | *(선택)* LSTM / TFT | 시퀀스 직접 | 관측률 90% 이상 키워드로 한정. **조건이 까다로운 이유는 §2-1** |

### 2-1. LSTM 이 시차 설계를 없애주지는 않는다

"시퀀스 모델을 쓰면 시차 열을 손으로 만들 필요가 없다" 는 맞다. 하지만 **윈도우가
없어지지는 않고**, 우리 데이터에서는 교환 조건이 나쁘다.

| | |
|---|---|
| 윈도우는 **모양만 바뀐다** | 지도학습 예측은 여전히 `(시퀀스 → 타깃)` 쌍이다. 고른 시차 7개 대신 원시값 T개가 들어가고 표가 2차원에서 `(배치, 시점, 특징)` 3차원이 될 뿐. 롤링 오리진도 그대로 필요하다 |
| **결측이 더 어려워진다** | LSTM 은 NaN 을 못 먹는다. 트리는 결측 분기를 학습하지만 dense 연산에는 NaN 의미가 없다 |
| ↳ 마스킹하면 | 그 시점을 건너뛰므로 **주 간격이 깨진다.** `t` 와 `t+2` 를 이웃으로 보게 되어 주간 계절성이 망가진다 |
| ↳ 채우면 | §4-1 에서 "ε 이 답을 만든다" 던 문제가 **선택이 아니라 필수**가 된다. 트리를 쓰는 이유 하나가 그걸 피할 수 있어서였다 |
| 계절성도 못 벗어난다 | 평범한 LSTM 은 100~200 스텝 창에서 lag 52 주기를 잡기 어렵다. 결국 `sin`/`cos` 나 작년 값을 따로 주게 된다 — 특징공학을 피한 게 아니다 |
| 표본이 작다 | 82만 행이지만 **독립 단위는 시계열 1,700개**다. 신생 키워드는 6스텝짜리라 패딩·마스킹이 또 필요하고, 격자(부모·형제)는 시퀀스가 아니라 정적 공변량으로 따로 꽂아야 한다 |

그래서 M4 에 **관측률 90% 이상**이라는 문지기를 뒀다. 결측이 거의 없는 구간에서만
전제가 성립하기 때문이다. **먼저 그 조건을 만족하는 키워드가 몇 개인지 센다.**
적으면 M4 는 버린다 — 1,700개 중 소수라면 모형 하나를 더 유지할 값어치가 없다.

## 2-2. M2 를 건너뛰지 않는 이유

M2 를 건너뛰지 않는 이유는 **해석** 때문이다. `φ_52` 가 유의하게 양수인지,
`φ_1` 이 음수(평균회귀)인지 양수(모멘텀)인지가 이 도메인에 대한 사실이고,
그게 없으면 M3 의 성능이 어디서 왔는지 말할 수 없다.

## 3. M2 — 패널 선형 AR

### 3-1. 식

주간 로그 변화율을 `r(i,t) = log( share(i,t) / share(i,t-1) )` 로 두면

```
y(i,t) = α
       + Σ_{l ∈ L}  φ_l · r(i, t-l+1)          자기회귀 항
       + β · log share(i,t)                     수준 (평균회귀 여부)
       + γ₁ sin(2πw/52) + γ₂ cos(2πw/52)        매끄러운 계절
       + γ₃ · r_seasonal(i,t)                   작년 같은 구간의 변화율
       + δ · obs_rate_8w(i,t)                   관측 상태
       + θ' · x_group(i,t)                      속성군 집계 (M2b 에서 추가)
       + ε(i,t)
```

- `L = {1, 2, 4, 8, 13, 26, 52}` — §7-2 의 시차 집합
- ⚠ **타깃은 4주 평균 비인데(§4-5) 위 `r` 은 아직 주 단위 점 대 점이다.**
  양쪽 해상도가 어긋난다. 어떻게 맞출지는 미결 — M2 구현 때 잔차를 보고 정한다
- `r_seasonal(i,t) = log( share(i,t-48) / share(i,t-52) )` — M0 과 같은 재료를 **변수로** 넣는다
- 추정: 릿지 / 엘라스틱넷. 시차끼리 상관이 세서 OLS 는 계수 부호가 흔들린다
- 표준오차는 **키워드 단위 클러스터**로 묶는다 (같은 키워드의 잔차는 상관된다)

### 3-2. 시차를 이렇게 고른 이유

| 시차 | 잡으려는 것 |
|---|---|
| 1, 2 | 최근 모멘텀 — 지난주에 오른 게 이번 주에도 오르나 |
| 4 | **타깃 지평과 같은 길이.** 직전 4주 변화가 다음 4주로 이어지나 |
| 8, 13 | 분기 리듬 · 시즌 전환 |
| 26 | 반년 — 간절기 뒤집힘 (가을 ↔ 봄) |
| 52 | **작년 같은 주.** 패션에서 가장 센 항일 가능성이 높다 |

52 를 시차로 넣는 것과 Fourier 항(`sin`/`cos`)을 같이 넣는 것은 중복처럼 보이지만 다르다.
Fourier 는 **모든 키워드가 공유하는 매끄러운 연중 곡선**이고,
시차 52 는 **그 키워드 자신의 작년**이다. 코트와 레깅스는 연중 곡선이 정반대다.

### 3-3. 왜 수준이 아니라 변화율인가

§7-2 에 이미 적었다. 요지는 키워드 간 `share` 수준이 36배까지 차이 나서,
수준을 타깃으로 두면 손실함수가 큰 키워드에 먹힌다는 것.

다만 **수준을 버리지는 않는다.** `β · log share(i,t)` 로 조건부에 남긴다.
이 계수의 부호가 그 자체로 결과다 — 음수면 "큰 키워드일수록 덜 오른다"(평균회귀),
0 에 가까우면 "크기와 성장률은 무관"이다.

## 3-4. 키워드 격자 — cold start 를 푸는 자리

§1 에서 "신규 키워드에는 자기 과거가 없다"를 패널로 푼다고 했는데, 그것만으로는 부족하다.
패널은 **계수**를 공유할 뿐 `올리브니트가디건` 의 시차 값 자체는 여전히 비어 있다.
빈 칸을 채우는 게 아니라, **비어도 쓸 수 있는 다른 칸**을 옆에 두는 것이 격자의 역할이다.

### 3-4-1. 분해와 조회

관측 키워드를 수식어 + 시드로 쪼갠다. **시드는 반드시 맨 뒤에 온다** — 한국어 명사
합성에서 핵이 마지막에 오기 때문이다(`니트가디건` ≠ `가디건니트`).

```
버건디니트가디건
   ├ 버건디가디건      수식어 하나 뺀 것
   ├ 니트가디건        수식어 하나 뺀 것
   └ 가디건            시드만
```

> **순서를 가린다 (실측).** `니트가디건` 41.2 vs `가디건니트` 1.2 — 34배 차이다.
> `버건디니트가디건` 과 `니트버건디가디건` 도 다른 시계열이다. 따라서
> **수식어를 정렬해 정규화하면 안 된다.** 둘은 별개 노드로 둔다.
> 다행히 "수식어를 하나씩 뺀다"는 방식은 남은 것들의 상대 순서를 자동으로 보존하므로
> 격자 생성 자체는 안전하다. 띄어쓰기는 무시되므로 공백만 제거해 맞춘다.

수식어 `k` 개면 노드가 `2^k` 개지만 실제로는 `k ≤ 3` 이고,
`가디건` 같은 상위 노드는 수십 개 리프가 공유하므로 중복 제거 후
실측(2026-10-28, 힌트 1개씩 단독 조회): 발굴 시드 24개의 수확 합계 **≈3,350 리프**.
여기에 **LLM 선별**(패션 여부·타깃 여부, 관련도 ~41%)이 걸려 **≈1,400** 이 남고,
중간 부모와 시드를 더해 **고유 노드 약 1,700개**가 된다.
배치당 4개(앵커 1칸 제외)로 전량 286회, 주간 갱신 월 1,150회 —
**한도 50,000건의 2.3%.** 비용은 제약이 아니다.

> **v0 은 훨씬 작게 시작한다** (`config/keywords.yaml` 의 `v0`). 시드 20개 ·
> 월 400~4,000 · 시드당 30개 → 리프 ~600 · 노드 ~720 · 호출 180회 · **35만 행**.
> 그 대역에서는 관측률 1.00 · 고유값비 0.80 이라(§4-0) **결측·양자화 대응 없이도 돈다.**
> 먼저 깨끗한 구간에서 파이프라인을 세우고, 대응 코드를 붙이면서 대역을 넓힌다.

> 힌트를 5개씩 묶으면 응답 한도를 나눠 써 뒤쪽 힌트가 잘린다 (스커트 15 → 단독 165).
> 그리고 **연관어가 정확히 1,200 인 시드가 16개** — API 상한이라 그 수확은 하한치다.

> **시드마다 편차가 극심하다.** 가디건 256 · 패딩 242 · 니트 230 인 반면
> 셋업 0 · 블레이저 1 · 크롭티 6 이다. 그래서 `config/keywords.yaml` 에서
> **`role: discovery` / `role: monitor`** 로 나눴다 — 후자는 자기 시계열만 수집하고
> 연관어를 받지 않는다 (주력 칸 §5-6 전용).
>
> **시드당 상한은 품질 장치가 아니다.** 규모 상위를 자르면 관련도가 **더 높은** 쪽을
> 버린다(발견 ⑩). 실제 선별은 LLM 이 하고, 상한 300 은 폭주 방지용이다.

> **부모 노드도 거른다.** 아무도 치지 않는 조합(`숄버건디가디건`)은 만들어 봐야 바닥에
> 눌린다. 검색광고 월간 검색수를 먼저 보고 **100~1만 구간에 드는 노드만** 조회한다.
> 이 사전 필터는 쇼핑인사이트 호출을 쓰지 않는다.

### 3-4-2. ★ 상위어는 하위어를 품지 않는다 (2026-10-27 실측)

설계 전에 반드시 확인해야 했던 것이고, 확인 결과 **포함 관계가 아니다.**

시계열을 실제로 뽑는 소스는 쇼핑인사이트이므로 **거기서 단독으로** 확인했다.
검색광고는 교차 확인용이다.

| | 검증 | 결과 |
|---|---|---|
| **쇼핑인사이트** | 부모 vs 자식 **12개**, 53주 | **53주 전부** 자식합 > 부모 |
| | 부모 ÷ 자식합 | 중앙값 **0.314** — 자식 12개만으로 부모의 3배 |
| | 그 비율의 1년 추이 | 0.47 → **0.16** (아래 주 참조) |
| 대조군 | `니트가디건` vs `니트 가디건` | 차이합 **0.0000** — 띄어쓰기는 무시 |
| 교차 확인 | 검색광고 `가디건` 자체 | 38,750 |
| | 검색광고 `…가디건` 440개 합 | **354,980** (자체는 11%) |
| | 검색광고 `여성가디건` | **44,160** — 자식 하나가 부모보다 크다 |

대조군이 중요하다. **정규화는 하는데 포함은 안 한다** — 공백을 지운 뒤의 정확 일치다.
`가디건` 은 "가디건이라고 **정확히** 친 사람"이고, 상위집합이 아니라 **형제**다.

> **부모 비중이 시간에 따라 줄고 있다.** 부모 ÷ 자식합이 1년 새 0.47 → 0.16 으로 떨어졌다.
> 질의가 점점 구체적으로 바뀐다는 뜻이고, 그래서 **시드 단독을 품목 시계열로 쓰면
> 실재하지 않는 하락 추세가 생긴다.** 합산이 선택이 아닌 이유가 하나 더 있는 셈이다.
> (분야 지수의 −43.5% 와는 별개 현상이다. 저건 카테고리 전체에서 측정한 값이다.)

**무너진 것**

- "부모가 자식을 떠받친다" — 부모는 자식의 집계가 아니므로 지지대가 될 수 없다
- `excess = 자식 − 부모` 를 집합 차집합으로 읽는 해석 — 뺄셈이 가리키는 집합이 없다
- **시드 단독 시계열 = 품목 시장** — 가디건 수요의 10분의 1만 보고 있던 셈이다

**살아남은 것 — 그리고 이게 핵심이었다**

cold start 는 포함 관계를 **요구하지 않는다.** `올리브니트가디건` 을 예측하는 데 필요한 건
`올리브가디건` 과 `니트가디건` 이 그것과 **상관된다**는 사실뿐이고, 그건 자명하다.
격자는 집계 계층이 아니라 **이웃 그래프**로 쓰면 된다. 시드-말단 규칙도 그대로 유효하다.

### 3-4-3. 격자에서 뽑는 열

```
depth           수식어 개수
n_mod

parent_growth   부모 노드들의 최근 4주 변화율 (평균 / 최대)
parent_level    부모 노드들의 현재 수준
parent_n        부모가 몇 개나 관측되고 있나        → 신뢰도
parent_lag52    부모의 작년 같은 주                 ★ 신생 키워드가 계절을 받는 유일한 통로
parent_seasonal 부모의 작년 같은 구간 변화율          (§4-2 ②)

sibling_growth  같은 부모를 공유하는 형제들의 변화율
                '니트가디건' 아래의 버건디·크롭·숄…

item_growth     품목군 — Σ over 관측된 '…가디건' 키워드
item_level      ★ 시드 단독이 아니라 합산이다 (§3-4-2)
mod_growth      수식어군 — Σ over '버건디' 가 붙은 모든 관측 키워드

rel_parent  = own_growth − parent_growth
rel_item    = own_growth − item_growth      이 조합이 품목 평균보다 빨리 크나
```

`rel_*` 은 **차집합이 아니라 상대 성장률**이다. 포함 관계가 깨졌으므로
"안에서의 초과분"으로 읽으면 안 되고, "형제·품목 평균 대비 빠른가"로만 읽는다.
신호로서의 쓸모는 그대로다.

**cold start 가 작동하는 방식**

```
올리브니트가디건, 관측 3주

lag_1 … lag_52      NaN          ← 자기 과거 없음
parent_growth       +18%         ← 올리브가디건 · 니트가디건에서
sibling_growth      +9%
item_growth         +4%
rel_parent          계산 불가(자기 성장률 부족) → NaN
```

M3(LightGBM)는 NaN 을 분기로 처리하므로 **자기 시차가 전부 비어도 행이 살아 있다.**
M2(선형)는 이런 행을 버리므로, **cold start 는 M3 의 고유 능력**이 된다 —
M2 대비 개선분이 어디서 왔는지 말할 수 있는 지점이기도 하다.

### 3-4-4. 걸림돌 두 개

**부모와 자식이 추천 목록에 같이 오르면 안 된다.** `니트가디건` 이 뜨면
`버건디니트가디건` 도 같이 뜬다. TOP 10 에 둘 다 들어가면 실제로는 8개만 추천한 것이고,
Precision@10 도 부풀려진다. **관측이 충분한 가장 구체적인 수준 하나만** 남긴다 —
목록 생성과 평가 양쪽에 같은 규칙을 적용한다.

**격자 가족 안에서 잔차가 상관된다.** 시간으로 자른 롤링 오리진은 행 간 의존을 못 막는다.
표준오차는 키워드가 아니라 **격자 가족(= 같은 시드를 공유하는 묶음) 단위로 클러스터**한다.

### 3-4-5. 성별은 키워드가 아니라 세그먼트로

실측에서 `여성가디건` 44,160 · `남자가디건` 31,630 · `남성가디건` 8,840 이 잡혔다.
시드 하나의 격자가 절반쯤 남성 수요다.

- `남자` · `남성` 은 `exclude_patterns` 로 격자 구성 단계에서 자른다 (이미 설정에 있다)
- `여성` 은 **접두어로 붙이지 않는다.** 쇼핑인사이트는 성별을 조회 파라미터로 받는다.
  `여성버건디니트가디건` 을 키워드로 치면 검색량이 쪼그라들어 양자화 바닥(`0.00437`)에
  바로 닿지만, `버건디니트가디건` 을 `gender=f` 로 뽑으면 같은 뜻인데 해상도가 훨씬 좋다

즉 **격자의 축은 성별·연령을 포함하지 않는다.** 그 둘은 조회 파라미터다.

## 4. 결측 — 이 모형의 제일 큰 난점

네이버는 관측되지 않은 주를 **응답에서 생략한다**. 0 이 아니라 행 자체가 없다.
자기회귀는 과거 값을 직접 먹으므로 여기서 바로 막힌다.

### 4-0. 실제로 얼마나 비는가 (2026-10-27 실측)

규모 필터(월 100~1만)를 통과한 키워드만 보면 **생각보다 적게 빈다.**
아래는 `가디건` 자식 15개를 105주 조회한 결과다 (앵커 `원피스`).

| 월 검색수 | 관측률 | 바닥률 | **고유값비** |
|---|---|---|---|
| 140 | 0.93 | 0.16 | **0.45** |
| 390 | 0.91 | 0.06 | 0.63 |
| 1,150 | 1.00 | 0.01 | 0.80 |
| 3,700 | 0.98 | 0.06 | 0.80 |
| 7,540 | 1.00 | 0.00 | 0.93 |

*고유값비 = 서로 다른 값의 수 ÷ 관측 주 수*

**진짜 제약은 결측이 아니라 마지막 열이다.** 하한 근처에서 105주 중 98주가 오지만,
서로 다른 값은 47개뿐이다. 값이 계단처럼 뭉쳐 있어 **증가율이 0인 주가 절반**이고
2차 차분인 가속도는 더 튄다. §2-1 의 양자화 바닥 문제가 여기서 다시 나온다.

두 가지 함의가 있다.

- **M2 의 complete-case 손실이 걱정보다 작다.** 관측률 0.9 이상이면 시차 7개가
  모두 차 있는 행의 비율이 쓸 만하다. 선형 모형을 포기할 이유가 없다
- **위 수치는 `원피스` 앵커로 잰 것이다.** 압도적으로 큰 앵커가 작은 키워드를 눌러
  고유값비를 떨어뜨린 몫이 크다. **규모별 앵커 사다리(§2-1)가 정확히 이걸 고친다** —
  사다리를 놓은 뒤 이 표를 다시 재서, 개선폭이 얼마인지가 사다리의 성과 지표가 된다

### 4-1. "0 으로 채우면 안 되나" — 가려서 답한다

직관은 틀리지 않았다. *"측정되기 전이면 아무도 안 쓴 것이고, 중간 결측도 임계값을
못 넘은 것이니 0 에 가깝다"* — **참값에 대해서는 대체로 맞는 말이다.**
문제는 참값이 아니라 **그 값에 씌우는 함수**다.

```
share 는 로그로 들어가고 타깃도 로그 비다
log(0) = −∞  →  숫자가 틀린 게 아니라 계산이 깨진다
```

그러니 질문은 **"0 대신 바닥값으로 채우면 안 되나"** 로 바뀐다. 여기가 진짜 쟁점이다.

#### 바닥값으로 채울 때 생기는 일 — 타깃이 상수로 결정된다

```
ε = 0.00437 (바닥) 로 채우고 첫 관측이 0.0131 이면
    y = log(0.0131 / 0.00437) = +1.10     → +200% 상승

ε = 바닥/10 이었다면
    y = log(0.0131 / 0.000437) = +3.40    → +2900% 상승
```

같은 데이터인데 답이 3배 다르다. **데이터가 아니라 내가 고른 ε 이 타깃을 만든다.**
그리고 이 행들이 하필 "막 떠오르는 키워드" 라서, 모형이 조기 탐지를 배워야 할 바로
그 자리에서 조작된 숫자를 배운다.

#### 중간 결측은 피해가 유계다 — 여기선 채워도 된다

`분홍색가디건`(월 140)은 관측률 0.93 · 바닥률 0.16 이다. 빠진 주의 참값은 바닥 미만이고
평소 값의 1/3 쯤 아래다. **무한대가 아니라 30% 수준의 왜곡**이다.
게다가 큰 키워드는 중간 결측이 거의 없다(관측률 1.00). 쟁점이 되는 구간 자체가 좁다.

#### 미탄생은 정확성이 아니라 표본 구성 문제다

480주 패널에 2024년생 키워드를 채우면 **350행이 합성, 100행이 실측**이다.
노드 1,700개에 이걸 다 하면 패널의 7할이 가짜가 되고, 모형이 용량을
"바닥 상수 맞히기" 에 쓴다. 손실함수가 그쪽에 먹힌다. 그래서 **행을 만들지 않는다.**

#### 결론 — 0 이냐가 아니라 어디에 쓰이느냐로 가른다

| | 처리 |
|---|---|
| **채워도 된다** — 맥락 특징 (롤링 평균 · 수준 · 군 합계) | 값이 덧셈으로 들어가고 상한(바닥)이 분명하다. **0 이 아니라 바닥값으로**, 플래그는 항상 동반 |
| **채우면 안 된다** — 타깃의 기준점 `s(t)` · `s(t+4)`, 증감률의 분모 | 지어낸 상수가 곧 답이 되는 자리다 |
| **행을 만들지 않는다** — `first_observed_at` 이전 | 표본이 가짜로 채워진다 |

나머지 둘은 어느 자리에서도 쓰지 않는다.

```
선형 보간            → 없던 추세를 지어낸다. 특히 조기 탐지 구간에서 치명적
전방 채우기만 하고 끝 → 결측이었다는 사실 자체가 신호인데 그걸 지운다
```

> **이것도 백테스트 항목이다.** 위는 추천일 뿐, 중간 결측을 바닥값으로 채우는 쪽이
> 더 낫게 나올 가능성은 충분하다. NaN / 바닥값 / 제외 세 가지를 돌려
> Precision@10 과 **신생 구간 Lead Time** 을 본다. 미결 목록에 올려 뒀다.

### 4-2. 빈칸은 세 종류다

| | 언제 | 뜻 | 처리 |
|---|---|---|---|
| `not_collected` | 그 구간을 **조회한 적이 없다** | 우리 쪽 공백 | **절대 채우지 않는다.** 백필로 고친다 |
| `pre_birth` | 조회했고, `first_observed_at` 이전 | 그때는 없던 말이다 | 행을 만들지 않는다. 시차로 걸리면 NaN |
| `censored` | 조회했고, 그 이후의 빈 주 | 그 주에 임계값 아래였다 | 행은 두고 NaN. 창 안에서는 바닥값 허용(§4-5) |

**첫 줄이 제일 위험하다.** 쇼핑인사이트는 2017-08 까지 소급되므로(§2-2),
"이 키워드는 최근 것뿐" 이 **사실인지 우리가 안 뽑은 건지** 반드시 갈라야 한다.
후자인데 바닥값을 넣으면 그냥 거짓말이다. `keyword_registry.backfilled_through` 가
이걸 지키는 장치다 — **백필이 끝나지 않은 구간에는 패널 행을 만들지 않는다.**

세 번째가 §4-1 에서 다룬 좌측 절단이다. 모르는 게 아니라 `(0, 바닥)` 구간이라는 걸
아는 것이므로, 0 은 구간 밖이라 틀리고 **바닥값은 구간의 상한**이라 의미가 있다.

#### 과거가 짧은 키워드 — 시차가 미탄생을 가리킬 때

```
키워드가 5~10기에만 존재.  L = {1, 2, 4, 8, 13, 26, 52}

t=10 행 (weeks_since_first_obs = 6)
   lag_1  → t=9   ✓        lag_8  → t=2   ✗  pre_birth → NaN
   lag_2  → t=8   ✓        lag_13·26·52   ✗  NaN
   lag_4  → t=6   ✓
```

**행이 죽지 않는다.** 시차 7개 중 3개가 살아 있고 나머지는 NaN 으로 둔다.
M3 는 결측 분기로 처리하고, 부족한 몫은 격자(부모·형제·품목군)와 달력이 메운다 —
§3-4 의 cold start 가 작동하는 자리가 정확히 여기다.

> **시차마다 사유 플래그를 달 필요가 없다.** `weeks_since_first_obs` 하나면
> `lag_l` 이 미탄생인지가 `l > weeks_since_first_obs` 로 결정된다. 변수 하나로 끝난다.
> (반면 `censored` 는 불규칙하므로 `lag_{l}_missing` 플래그가 따로 필요하다.)

**학습 가능 시점과 예측 가능 시점이 다르다.** 라벨은 미래 창을 요구하기 때문이다.

```
예측   base 창(t-3…t) 에 관측 ≥2   → 태어나고 2~4주면 순위표에 오를 수 있다
학습   fut 창(t+1…t+4) 까지 필요   → 라벨 달린 첫 행은 ~8주 뒤
```

위 예에서 라벨이 붙는 마지막 시점은 `t=6` 이다 — base 는 3·4·5·6 기인데 관측이
5·6 둘뿐이라 `min_count 2` 를 간신히 넘고, fut 는 7~10 기로 꽉 찬다.

**M2 는 이 행들을 전부 버린다** (complete-case). 설계대로지만, 그래서
M2 와 M3 를 전체 모집단에서 비교하면 M2 에 불공평하다 — §4-4 의 "M3 를 두 번 돌린다" 가
이 문제를 처리한다.

#### 실제 행 모양

`t5=0.012 · t6=0.015 · t7=검열 · t8=0.021 · t9=0.026 · t10=0.031`,
오늘 10기, `first_observed_at=5`, 백필 1기까지 완료.

| t | share | 상태 | wk_since | lag1 | lag2 | lag4 | lag8 | base | fut | y | split |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1~4 | — | `pre_birth` | — | — | — | — | — | — | — | — | **행 없음** |
| 5 | 0.012 | obs | 0 | NaN | NaN | NaN | NaN | n=1 ✗ | — | — | `drop` |
| 6 | 0.015 | obs | 1 | 0.012 | NaN | NaN | NaN | 0.0135 | 0.0206 | **+0.42** | `train` |
| 7 | NaN | `censored` | 2 | 0.015 | 0.012 | NaN | NaN | — | 미래 | — | `feature` |
| 8 | 0.021 | obs | 3 | NaN | 0.015 | NaN | NaN | — | 미래 | — | `feature` |
| 9 | 0.026 | obs | 4 | 0.021 | NaN | 0.012 | NaN | — | 미래 | — | `feature` |
| 10 | 0.031 | obs | 5 | 0.026 | 0.021 | 0.015 | NaN | 0.0245 | — | — | **`predict`** |

- `t=9` 의 `lag2` 는 **검열**로, `lag8` 은 **미탄생**으로 비었다. 전자는 `lag2_missing`,
  후자는 `wk_since=4 < 8` 로 구분된다
- `t=6` 만 라벨이 붙는다. fut 의 7기 검열은 바닥값으로 채워
  `(0.00437+0.021+0.026+0.031)/4 = 0.0206`
- **라벨 없는 행도 지우지 않는다.** `feature` 행은 다른 행의 시차와 군 집계에 재료로 들어간다

#### 이 상태로 학습이 되는가

기계적으로는 된다 — LightGBM 은 결측을 별도 분기로 보내므로 행이 버려지지 않는다.
다만 **"돌아간다" 와 "배운다" 는 다르고**, 셋을 챙겨야 한다.

| | 문제 | 처방 |
|---|---|---|
| ① | **모집단이 섞인다.** 시차가 꽉 찬 성숙 키워드와 텅 빈 신생이 한 손실함수에 있어, 시차의 유용성이 평균되어 과소평가된다 | **`weeks_since_first_obs` 가 열쇠다.** 트리가 이걸로 먼저 쪼개면 "어리면 격자를, 오래됐으면 시차를" 이 명시적 분기가 된다. 한 모형이 두 모형처럼 행동한다 |
| ② | **`lag_52` 가 구조적으로 불리하다.** 패션에서 제일 셀 항인데 1년 미만 키워드는 영원히 NaN | 부모는 대개 오래됐다. **`parent_lag52` · `parent_seasonal` 을 격자 열에 추가**해 자식 행에 붙인다 |
| ③ | 시차도 부모도 전부 NaN 인 행은 가르칠 게 없고 잡음만 보탠다 | **학습 행 최소 조건** — `lag_1` 또는 `parent_growth` 중 하나는 있어야 한다. 예측에는 그대로 쓴다 |

> **비중은 과하지 않다.** 2024년생 키워드도 52주를 넘기면 이후 행은 시차가 다 찬다.
> 키워드당 불완전한 행은 처음 ~52개뿐이고 패널 전체로는 1~2할 수준이다.
> 문제가 **국소적이고 식별 가능**하다.

> **이건 가정이지 확정이 아니다.** 신생과 성숙을 한 모형에 섞는 게 나은지,
> 둘로 나눠 라우팅하는 게 나은지는 돌려봐야 안다. 검증은 분명하다 —
> **통합 모형의 신생 구간 성능을 신생만으로 학습한 모형과 비교**해서
> 통합 쪽이 나쁘면 섞은 것이 해가 된 것이다. 미결에 올린다.

### 4-3. 자리마다 처방이 다르다

| | 자리 | 처방 |
|---|---|---|
| ① | **타깃** `y = log(s(t+4)/s(t))` | 두 시점이 다 있어야 한다. 하나라도 비면 **라벨 없는 행** — 학습에서 제외, **예측에는 그대로 쓴다**(예측엔 y 가 필요 없다). **라벨은 절대 상상해서 채우지 않는다** |
| ② | 시차 · 증감률 | NaN 유지 + `lag_{l}_missing`. M3 는 트리가 결측 분기를 학습, M2 는 행을 버린다 |
| ③ | 롤링 통계 | `min_count` 를 건다. 8주 중 2주로 만든 평균을 8주 평균이라 부르지 않는다 |
| ④ | **군 집계** | 아래 별도 |
| ⑤ | `at_floor` | 결측은 아니나 같은 뿌리. 한 칸 상승이 +100% 로 보이므로 가중치 ↓ 또는 제외 |

#### ①의 숨은 편향 — 반드시 감시한다

버려지는 행은 **그 키워드가 바닥으로 꺼졌던 주**에 몰린다. 무작위 결측이 아니다.
학습 데이터가 "관측된 = 비교적 큰" 상태 쪽으로 쏠린다. 없앨 수 없으므로 **진단으로 본다** —
매 학습마다 남은 행과 버린 행의 `share` 분포를 비교해 치우친 정도를 기록한다.

#### ④ 군 집계 — 여기가 제일 위험하다

속성군·격자군 시계열을 **그냥 더하면 안 된다.**

```
지난주  버건디군 = 가디건 + 니트 + (스커트 결측)      합 0.043
이번주  버건디군 = 가디건 + 니트 +  스커트            합 0.064   → +49% ?!
```

멤버가 돌아온 것이 "버건디가 떴다"로 읽힌다. 멤버 구성이 주마다 바뀌므로
**합의 변화가 수요의 변화가 아니다.** 처방은 둘 중 하나다.

```
균형 패널   t 와 t-4 양쪽에 다 관측된 멤버만으로 두 시점을 비교한다   ← 권장
관측 평균   합 대신 관측 멤버 평균을 쓰고 n_obs 를 같이 넣는다
```

전자가 깨끗하다. 비교 구간마다 멤버 집합이 달라지지만, 그 집합 안에서는 정의가 일관된다.
품목 시계열(§3-4-2 의 `…시드` 합산)에도 같은 규칙을 적용한다.

### 4-4. 모형마다 다르게

| | M2 (선형) | M3 (LightGBM) |
|---|---|---|
| 시차가 빈 행 | **제외** (complete case) | **NaN 으로 두고 넣는다** — 트리가 결측 분기를 학습한다 |
| 결측 표시 | — | `lag_{l}_missing` 플래그 동반 |
| 공통 | `obs_rate_8w` 를 변수로 · `at_floor` 행은 가중치 ↓ 또는 제외 | 좌동 |

> **비교할 때 표본을 맞춘다.** 위 처리가 다르면 M2 와 M3 의 학습 행 수가 달라져
> 성능 차이가 모형 때문인지 표본 때문인지 구분이 안 된다.
> **M3 를 두 번 돌린다** — ⓐ NaN 허용 전체, ⓑ M2 와 같은 complete-case.
> M2 와 비교할 때는 ⓑ 를, 실제 운용에는 ⓐ 를 쓴다.

### 4-5. 타깃 기준점이 검열되면 — 정의를 바꿔서 푼다

§4-1 의 규칙("타깃 기준점에는 채우지 않는다")을 그대로 적용하면 막힌다.
`s(t)` 가 검열된 주면 라벨이 없고, 그런 행을 전부 버리면 **키워드가 꺼졌던 주**가
통째로 사라져 §4-3 의 편향이 커진다. 선택지를 고르는 대신 **타깃 정의를 바꾼다.**

```
base = mean( s, t-3 … t   )
fut  = mean( s, t+1 … t+4 )
y    = log( fut / base )
```

세 가지가 한꺼번에 풀린다.

| | |
|---|---|
| 검열 한 주가 행을 죽이지 않는다 | 4주 중 1~2주가 비어도 평균이 남는다 |
| **창 안에서는 바닥값으로 채워도 된다** | 한 주가 1/4 가중치로만 들어간다. §4-1 이 금지한 건 지어낸 상수가 **답을 통째로 결정**하는 경우인데, 평균 안에서는 그 지배력이 사라진다 |
| 편향이 상쇄된다 | 분자·분모에 같은 규칙을 쓰면 바닥값 채우기가 양쪽을 같은 방향으로 민다. 로그 비에서 상당 부분 지워진다 — 점 대 점일 때는 안 되던 것 |

덤으로 **의사결정에 더 맞는 질문이 된다.** 사입은 특정 한 주를 맞히는 일이 아니라
"다음 달쯤 뜨는가" 를 맞히는 일이다. 점 대 점 비율은 애초에 질문보다 날카로웠다.

남는 규칙은 이것뿐이다.

```
창 4주 중 관측 ≥ 2   → 행 유지. 검열 주는 바닥값으로 채워 평균
          < 2        → 행 제외 (라벨 없음)
항상                 → y_base_censored_n 플래그 동반, 진단에서 감시
```

> **대가.** 기준을 4주 평균으로 두면 탐지가 늦어질 수 있다. 다만 한 점 기준은
> 계단(고유값비 0.45)에 파묻혀 있어 실제로는 평균 쪽이 **더 일찍** 잡을 가능성이 크다.
> 두 정의를 백테스트로 비교한다 — 미결 목록에 있다.

### 4-6. 결측을 신호로 쓰는 쪽

트랙 A(신조어)에서는 결측률 자체가 판정 지표다 (§2-3).
`obs_rate_8w` 가 0.2 → 0.6 → 0.9 로 오르는 것은 "네이버가 이 말을 세기 시작했다"는 뜻이고,
`share` 의 상승률보다 먼저 움직인다. 모형 안에서는 `δ` 가 이 효과를 흡수한다.

## 5. 두 가지 출력 — 예측과 놀라움

같은 모형에서 두 개가 나오는데 **시점이 다르다.** 자주 헷갈리는 지점이라 분리해 둔다.

```
지금이 T 주라면

예측   ŷ(i,T)                        → 앞으로 4주간 얼마나 오를까
                                       "뜨는 것" 칸의 순위 = ŷ 내림차순
                                       되돌릴 필요 없음 (순위만 쓰므로)

놀라움 y(i,T-4) − ŷ(i,T-4)            → 4주 전 예측이 얼마나 빗나갔나
                                       계절·관성으로 설명 안 되는 움직임
                                       4주 지연 신호 — 추천이 아니라 감시용
```

놀라움은 **실제 `y` 가 필요하므로 `T-4` 까지만 계산된다.** 이걸 추천 순위로 쓸 수 없다.
쓰임은 따로 있다 — 특정 속성군에서 놀라움이 연속으로 양수면
"이 군에 모형이 모르는 무언가가 생겼다"는 뜻이고, 레짐 변화나 신규 축의 등장을 가리킨다.

예상 수준이 필요하면 되돌린다: `share(i,T+4) ≈ share(i,T) × exp(ŷ)`.
다만 **리포트에 수준 예측치를 적지 않는다** — 불확실성 대비 과도하게 구체적으로 읽힌다.

## 6. 추정과 평가

### 6-1. 분할

롤링 오리진, 폴드 사이 **4주 공백** (§7-2). 공백이 없으면 학습 마지막 행의 타깃이
평가 구간에 걸쳐 샌다.

```
[───── 학습 ─────][ 4주 ][ 평가 ]
        [───── 학습 ─────][ 4주 ][ 평가 ]
                [───── 학습 ─────][ 4주 ][ 평가 ]
```

학습 구간 길이는 미정이다 — 2017년부터 전부 쓸지 최근 3년만 쓸지.
플랫폼 드리프트를 점유율로 걷어냈다지만 소비 행태 자체가 바뀌었을 수 있어,
**두 설정을 모두 돌려 비교한다.**

### 6-2. 손실과 가중치

- 손실: Huber (`y` 는 로그비라 꼬리가 두껍다. 한 칸 양자화 점프가 이상치를 만든다)
- 가중치: `at_floor` 행 ↓. **작은 키워드를 다운웨이트하지 않는다** — 그게 타깃이다
- 다중 지평: `h ∈ {2, 4, 6}` 을 **각각 별도 모형**으로 (직접 예측). 재귀 예측은 안 쓴다 —
  오차가 누적되고 결측 구간에서 발산한다

### 6-3. 지표

| | 지표 | 왜 |
|---|---|---|
| 주 | **Precision@10** | 사입은 한 회차에 몇 품목뿐. 상위 10개 적중률이 곧 쓸모 |
| 주 | **Lead Time** | 피크보다 몇 주 먼저 알렸나. 2~6주를 못 벌면 맞혀도 소용없다 |
| 주 | **False Alarm Rate** | 오탐 비용이 비대칭 (§5-5) |
| 보조 | 스피어만 순위상관 (`ŷ` vs 실제 `y`) | 전체 순위가 맞는지 |
| 보조 | MAE / RMSE | 리포트하되 **모형 선택 기준으로 쓰지 않는다** |

마지막 줄이 중요하다. RMSE 가 낮아도 상위 10개가 틀리면 이 시스템은 실패다.
**모형 선택은 Precision@10 으로 한다.**

### 6-4. 진단 — 통과해야 할 것

| 진단 | 무엇을 의심하나 |
|---|---|
| 키워드별 잔차 자기상관 | 남아 있으면 **시차가 부족**하다 |
| 주차별 평균 잔차 | 특정 주차에 쏠리면 **계절항이 부족** |
| `log share` 구간별 잔차 | 수준에 따라 편향되면 `β` 가 선형으로는 부족 |
| 규모대별 성능 | 작은 키워드에서만 무너지면 **양자화 바닥 문제** (§2-1) |
| 관측률 구간별 성능 | 결측 처리(§4-3)가 적절한지 |
| **`weeks_since_first_obs` 구간별 Precision@10** | 신생 키워드 행이 많으면 집계 지표가 뭉개진다. **오래된 키워드로만 점수를 벌고 있는지** 확인 — 조기 탐지가 목적이므로 이 분할이 본 지표에 가깝다 |

## 7. 수용 기준 — 언제 다음 칸으로 가나

```
M2 가 M0·M1 을 Precision@10 에서 이긴다        → M3 로 간다
M2 가 못 이긴다                                 → 모형을 키우지 않는다
                                                  데이터(해상도·결측·세그먼트)를 먼저 고친다
M3 가 M2 를 못 이긴다                           → 속성 레이어의 값어치가 없다는 결과.
                                                  그대로 보고하고 M2 를 쓴다
```

세 번째 줄도 **결과다.** "속성을 넣었더니 안 좋아졌다"는 것은 실패가 아니라 측정이다.
§0 의 "안 맞을 때 안 맞는다고 측정할 수 있게 설계했는가"가 이 지점에서 시험받는다.

## 8. 주력 칸(§5-6)과의 관계

**평년 곡선은 모형이 아니다.** 과거 N년 주차별 점유율 중앙값이라는 기술통계다.
모형의 Fourier 항·시차 52 와 재료는 같지만 쓰임이 다르다.

| | 평년 곡선 | 모형 |
|---|---|---|
| 대상 | 시드 32개 (주력) | 격자 노드 약 1,700개 (뜨는 것) |
| 출력 | 지금 위치 · 피크 잔여주수 · 편차 | 4주 뒤 변화율 예측 |
| 추정 | 없음 (중앙값) | 있음 |

주력 칸이 모형을 안 쓰는 이유는 간단하다 — 주력 품목은 **예측이 쉽고 가치가 낮다.**
가디건이 가을에 오른다는 걸 맞혀 봐야 셀러가 이미 안다.
거기서 가치 있는 건 예측이 아니라 **비교 기준**(평년 대비 어디인가)이다.

## 9. 구현 순서

[PROGRESS.md](PROGRESS.md) 의 작업 번호와 맞춘다.

```
3  수집 + 캐시
4  panel 뼈대 (속성 없이)        ← M2 가 먹을 표
5  백테스트 틀 (롤링 오리진)      ← 먼저. 없으면 좋은지 나쁜지 모른다
6  M0 · M1 베이스라인
   ──────────────────────────── 여기까지가 비교의 바닥
   M2 패널 선형 AR               ← 자기회귀 본체. 계수 해석 포함
7  LLM 속성 분해
8  M3 LightGBM
   M4 (선택)
```

5·6 을 7·8 보다 먼저 한다는 원칙은 그대로다.
**M2 는 속성이 필요 없으므로 6번 직후에 바로 붙는다** — 7번(Anthropic 키 필요)을
기다리지 않아도 된다. 지금 당장 막혀 있는 건 1·2·3번뿐이다.

## 미결

백테스트로 정할 것과 미팅으로 정할 것을 갈라 둔다.
**아래 하이퍼파라미터를 한꺼번에 훑지 않는다** — 격자 깊이와 결측 임계는
표본 크기를 바꾸므로 먼저 고정하고, 그다음 모형 쪽을 돌린다.

### 결측 처리 (§4) — 백테스트로

| 항목 | 후보 | 판단 기준 |
|---|---|---|
| 롤링 `min_count` (8주 기준) | **3 · 5 · 6** | 높일수록 통계가 정직해지지만 **신생 키워드 행이 날아간다.** 조기 탐지가 목적이라 그 손실이 치명적일 수 있다 → Precision@10 과 **신생 구간 Lead Time 을 같이** 본다 |
| `at_floor` 처리 | 제외 vs 가중치 0.3 | 제외하면 소규모 키워드가 통째로 빠진다. 가중치 쪽이 안전해 보이나 미확인 |
| 군 집계 방식 | 균형 패널 vs 관측 멤버 평균 | 권장은 균형 패널(§4-3 ④). 둘의 차이가 실제로 얼마나 나는지 먼저 측정 |
| **타깃 정의** | 4주 평균 비 vs 점 대 점 `log(s(t+4)/s(t))` | 평균 쪽이 검열에 강하지만 탐지가 늦어질 수 있다. Lead Time 으로 가른다 |
| **창 최소 관측 수** | 2 · 3 (4주 중) | 높이면 라벨이 정직해지고 행이 줄어든다 |
| **중간 결측 보간** | NaN · 바닥값 · 행 제외 | §4-1 의 추천은 NaN 이지만 피해가 유계라 바닥값이 이길 수 있다. 타깃 기준점에는 어느 경우에도 쓰지 않는다 |
| `obs_rate` 창 길이 | 8주 vs 13주 | 트랙 A 졸업 판정과 같은 창을 쓸지 |

### 격자 (§3-4) — 수집해 보고

- 노드 깊이 상한 — `k ≤ 2` 로 자를지 3까지 둘지. **바닥에 닿는 비율을 보고 정한다**
- 시드당 상한 — 가디건 181 vs 셋업 0 의 편차를 어디서 끊을지 (60개 선)
- 부모가 여럿일 때 `parent_*` 를 평균으로 접을지 최대·최소를 따로 둘지

### 모형 (§2~3)

- 학습 구간 — 2017년부터 전부 vs 최근 3년
- 시차 집합 `L` — 위는 출발점. 잔차 자기상관 보고 가감
- **설명변수의 해상도를 타깃에 맞출지** — 타깃은 4주 평균 비(§4-5)인데 자기회귀 항
  `r(i,t) = log(s(t)/s(t-1))` 은 주 단위다. 시차 1·2 는 그대로 두고 4 이상만 4주 평균
  기준으로 바꾸는 안이 유력하나, **M2 를 돌려 잔차 자기상관을 보고 정한다.**
  지금 바꾸면 무엇이 효과였는지 분리가 안 된다
- `h` 를 4주 하나로 할지 {2,4,6} 세 개로 할지
- 정규화 종류와 세기 (릿지 vs 엘라스틱넷)
- 속성군 집계·격자 열을 M2 에 넣을지(M2b) M3 부터 넣을지 — 선형에서도 보고 싶긴 하다
- **M4 를 시도할지** — 먼저 관측률 90% 이상 키워드 수를 센다(§2-1). 소수면 버린다
- **신생·성숙을 한 모형에 섞을지 둘로 나눠 라우팅할지** — 통합 모형의 신생 구간 성능을
  신생 전용 모형과 비교해 정한다 (§4-2)
