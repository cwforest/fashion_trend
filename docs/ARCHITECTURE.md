## 0. 이 프로젝트의 이중 목표

이 시스템은 두 가지를 동시에 노린다. 충돌하면 **포트폴리오를 우선한다** —
사업 검증은 수개월이 걸리지만 포트폴리오는 수 주 안에 완성되고, 전자가 실패해도 후자는 남는다.

| | 성공 조건 | 평가 방식 |
|---|---|---|
| **포트폴리오** | 안 맞을 때 안 맞는다고 측정할 수 있게 설계했는가 | 백테스트 지표 (§6) |
| **사업 검증** | 친구가 매주 실제로 열어보는가 | 사용 로그 + 사후 사입 이력 대조 |

정확도보다 **검증 설계가 산출물**이다. 모델이 틀릴 수 있다는 전제 위에서, 틀린 정도를
정량화하는 구조를 갖추는 것이 이 프로젝트가 보여줄 역량이다.

**사용자**: 에이블리에서 여성 의류를 판매하고 동대문에서 직접 사입하는 소규모 셀러
**주 고객층**: 10~20대 여성 (→ 모든 수집에 성별·연령 세그먼트를 건다)
**의사결정 주기**: 주 1회 · **예측 지평**: 2~6주 (사입 1~3일 + 촬영·등록 2~3일 + 초기 반응 1~2주)

### 1-4. 분석 단위가 "상품"이 아닌 이유

쇼핑 검색 API 종료로 상품 단위 데이터를 공식 경로로 얻을 수 없다.
따라서 이 시스템의 분석 단위는 **검색어 → 패션 속성**이다.
속성 조합을 실제 사입 품목으로 번역하는 마지막 한 걸음은 사람(셀러의 감)이 맡는다.

### 1-5. 수기 관찰 — 유일한 정답지

플랫폼 랭킹(에이블리·지그재그·무신사우먼)은 API가 없어 자동 수집이 불가능하고
소급도 안 된다. 그런데 **그게 정답지 그 자체**다. 네이버 지수가 올라간 속성이 실제로
랭킹에 올랐는지는 이것 없이는 검증할 방법이 없다.

주 1회 30분, **같은 요일·같은 시간**에 아래를 기록한다.

| 보는 곳 | 무엇을 | 왜 |
|---|---|---|
| 플랫폼 랭킹 상위 50 | 에이블리 · 지그재그 · 무신사우먼 | 우리 고객이 실제로 사는 것. 가장 직접적인 정답지 |
| 신상마켓 신상 피드 | 도매가 밀고 있는 것 | **최상류.** 여기 반복 출현한 디테일이 2~4주 뒤 랭킹에 온다 |
| 인스타 · 틱톡 | 인플루언서 피드의 반복 아이템 | 10~20대의 발원지. 정량화는 포기하고 반복 출현만 센다 |

기록 형식을 지금 고정해야 나중에 모델 입력이 된다. 메모장에 흘려쓰면 데이터가 안 된다.

```csv
observed_at,source,rank,item,silhouette,material,color,pattern,detail,style,price_krw,note
2026-10-21,ably,3,원피스,벌룬,새틴,블랙,무지,퍼프소매,로맨틱,29800,
2026-10-21,sinsang,,자켓,오버사이즈,트위드,아이보리,무지,골드버튼,프레피,42000,도매 여러 곳 동시 출현
```

- `source`: ably / zigzag / musinsa / sinsang / instagram / tiktok
- 속성 칸은 `config/taxonomy.yaml` 의 값을 쓴다 (자동 매핑과 호환된다)
- **몰라도 비워둔다. 빈칸이 오답보다 낫다**
- `note` 의 "여러 곳에서 동시 출현" 같은 메모가 제일 값지다

> **우선순위는 2순위다.** 쇼핑인사이트 소급 조회(§2-2)로 백테스트가 오늘 당장 되므로,
> 모델 검증을 위해 8주를 기다릴 필요가 없다. 수기 관찰의 역할은 모델 검증이 아니라
> **"검색 관심도 ≠ 에이블리 실판매" 간극을 메우는 보완재**다.
> 다만 플랫폼 랭킹은 소급이 불가능하므로 그 용도로는 지금부터 쌓아야 한다.

## 2. 핵심 설계 결정 세 가지

### 2-1. 앵커 체이닝 — 배치 간 비교 가능성 확보

> 2026-10-22 실측으로 개정. 아래 수치는 쇼핑인사이트 API 직접 호출로 확인한 값이다 (탐침 코드는 보관하지 않음).

쇼핑인사이트의 `ratio`는 **그 요청 안에서** 최댓값을 100으로 둔 상대값이다.
요청당 키워드 5개 제한(6개를 넣으면 400) → 키워드 1,000개를 보려면 250번 쪼개야 하고,
**배치끼리 값이 서로 비교 불가능**하다.

**해결**: 모든 배치에 고정 **앵커** 키워드를 1개 끼워 넣고 앵커 레벨로 배치 전체를 나눈다.

```
chained_index(k, t) = ratio_batch(k, t) / mean_t( ratio_batch(anchor, t) )
```

- 배치당 가용 슬롯이 키워드 4개로 줄지만 공통 단위를 얻는다
- 앵커 조건: 연중 꾸준한 검색량 + 급변하지 않는 범용어 (기본값 `원피스`)

#### 이 보정은 근사가 아니라 항등식이다

배치 안의 모든 값은 **하나의 분모** `M_batch`(그 요청의 최댓값)로 나뉜 값이다.

```
ratio_batch(k,t) = v(k,t) / M_batch        ← M 은 키워드와 무관, 배치마다 하나
chained(k,t)     = ratio_batch(k,t) / mean_t(ratio_batch(anchor,t))
                 = v(k,t) / mean_t(v(anchor,t))        ← M_batch 가 약분된다
```

배치 구성과 무관하게 **오차 0으로 약분된다.** 실측도 그렇다 — 가디건·니트를 같이
조회한 비율(정답)과 따로 조회해 앵커로 보정한 비율의 상대오차가 26주 전 구간에서
중앙값·평균·최대 모두 0.0%였다.

따라서 §6-2에서 "앵커 후보를 바꿔가며 오차가 가장 작은 것을 고른다"는 **의미가 없다.**
어떤 앵커를 써도 오차는 0이다. 검증해야 할 것은 스케일 정합이 아니라 아래 두 가지다.

#### 진짜 제약 ①: 양자화 바닥 — 앵커 하나로는 안 된다

`ratio`는 **소수점 5자리**에서 끊긴다. 앵커가 압도적으로 크면 작은 키워드가 바닥에 눌린다.

26주 실측 (앵커 `원피스`와 함께 조회):

| 키워드 | 최솟값 | 최댓값 | 관측 구간 |
|---|---|---|---|
| 원피스 (앵커) | 24.77124 | 100.0 | 26 / 26 |
| 스웨이드자켓 | 0.28895 | 45.09872 | 26 / 26 |
| 벌룬스커트 | 0.84497 | 2.71441 | 26 / 26 |
| 발레코어 | **0.00437** | 0.08318 | 18 / 26 |
| 바라클라바 | **0.00437** | 0.03502 | 9 / 26 |

두 키워드의 최솟값이 똑같이 `0.00437`이다. 이게 바닥이다. 월간 조회에서는 바라클라바가
네 구간 내리 `0.0131`로 고정돼 나왔다 — 값이 안 변한 게 아니라 **해상도를 잃은 것**이다.
증가율·가속도가 계단식으로 튀므로, 조기 탐지가 노리는 소규모 신생 키워드에서 바로 문제가 된다.

**대응: 단일 앵커를 버리고 규모별 사다리를 놓는다.**

```
대형대  원피스 · 청바지 · 니트        ← 지수 10~100
         └ 중간앵커 A (두 대역에 모두 넣는 중간 규모 키워드)
중형대  A · 벌룬스커트 · 스웨이드자켓  ← 지수 0.1~10
         └ 중간앵커 B
소형대  B · 발레코어 · 바라클라바      ← 지수 0.001~0.1

chained(k) = ratio(k) / mean(ratio(B)) × scale(B→A) × scale(A→원피스)
```

약분이 항등식이므로 사다리를 여러 단 이어도 오차가 누적되지 않는다.
다만 각 단계의 중간 앵커는 **두 대역 모두에서 바닥에 눌리지 않는 크기**여야 한다.

운영 절차:
1. 신규 키워드는 먼저 기본 앵커와 함께 1회 조회해 대략의 규모를 잰다
2. 규모대(대/중/소)에 배정한다
3. 이후 정기 수집은 같은 대역 안에서, 그 대역의 앵커와 함께 돈다
4. 규모가 변해 바닥에 닿거나 천장을 치면 대역을 재배정한다

#### 진짜 제약 ②: 결측은 0이 아니다

네이버는 관측치가 없는 구간을 **아예 응답에서 뺀다.** 위 표에서 바라클라바는 26주 중
9주만 돌아왔다. 검색이 0이었는지, 임계값 아래라 생략된 건지 응답만으로 구분되지 않는다.

- `raw_observation`에는 **온 것만** 넣는다. 없는 주를 0행으로 채우지 않는다
- 지표 계산 단계에서 결측 처리 규칙을 명시한다. 0으로 메우면 "급등"이 조작되고,
  앞값으로 메우면 "지속성"이 조작된다
- **결측률 자체를 신규성 지표로 쓴다.** 결측이 줄어드는 것(= 네이버가 보내기 시작하는 것)이
  신생 키워드의 가장 이른 신호일 수 있다 → §6-2에서 검증

**절대 스케일 환산** (선택): 검색광고의 월간 검색수 절대값, 또는 KOSIS 월간 거래액으로
상대지수를 실수치 축에 올린다.

```
수요추정(k,t) ≈ 절대규모(검색광고, 월) × 세그먼트비중(쇼핑인사이트) × 주간추이(쇼핑인사이트)
```

### 2-2. 소급 백테스트 — 오늘 당장 검증할 수 있다

쇼핑인사이트는 **2017-08-01부터 소급 조회**가 된다. 이것의 의미가 크다.

1. **이번 주에 처음 발견한 키워드도 즉시 과거 시계열을 채울 수 있다.**
   "발견 → 1년 기다려 계절성 확인"이 아니라 "발견 → 그 자리에서 작년 패턴 확인"
2. **데이터를 쌓기 시작할 필요 없이 오늘 백테스트가 가능하다.**
   "2026-06-01 시점에 이 모델이 뽑은 TOP 10이 이후 8주간 올랐나?"를 바로 돌린다

→ 키워드 레지스트리를 누적 관리하고, 신규 등록 시 과거 구간을 자동 백필한다.

### 2-3. 두 발굴 경로 — 경쟁이 아니라 역할 분담

> 2026-10-22 개정. 원안은 두 경로를 같은 지표로 **경쟁**시키는 것이었다.
> 실측 결과 둘이 보는 대상이 달라서, 겨루게 하는 대신 일을 나눈다. 비교 실험은 뒤로 미룬다.

두 경로가 찾는 것이 구조적으로 다르다.

| | 경로 A — LLM 웹 검색 | 경로 B — 검색광고 연관어 |
|---|---|---|
| 입력 | 패션 기사·콘텐츠 | 시드 품목 |
| 찾는 것 | **아직 검색량이 없는 신조어** | 이미 검색되는 조합어 |
| 과거 데이터 | 거의 없음 (소급해도 결측) | 2017-08 까지 소급 가능 |
| 약점 | 공급측 의도 편향, 재현성 낮음 | **월 10회 미만은 `< 10` 으로 가려져 아예 안 보임** |

경로 B 는 구조적으로 신조어를 못 본다. 검색광고가 이미 검색되는 말만 돌려주기 때문이다.
반대로 경로 A 가 찾은 신조어는 과거가 비어 있어 모형을 적합할 수 없다.

**그래서 탐지 방법도 트랙별로 다르다.**

```
트랙 A  신조어       LLM 웹검색 발굴 → 쇼핑인사이트에서 "잡히기 시작했나" 관찰
                     판정 기준: 상승률이 아니라 **관측률**
트랙 B  기존 조합어  연관어 발굴 → 패널 모형으로 상승 탐지
                     판정 기준: 점유율 상승률 · 가속도 · 지속성 · 놀라움
```

#### 트랙 A 의 판정 — 관측률을 쓴다

신조어는 양자화 바닥(`0.00437`)에 걸려 상승률이 계단식으로 튄다.
대신 **네이버가 그 검색어를 세기 시작했는지**를 본다.

```
관측률(k, 최근 N주) = 값이 온 주 수 / N
```

26주 중 9주만 오던 키워드가 최근 8주 중 7주를 보내기 시작했다면,
수치가 작아도 **네이버 안에서 존재감이 생기고 있다는 뜻**이다. §2-1 의 결측 제약을
역으로 신호로 쓰는 것이다. 이 가설은 §6-2 에서 검증한다.

#### 졸업 — A 에서 B 로

트랙 A 키워드가 충분히 관측되면 모형이 다룰 수 있게 된다.

```
A → B 조건:  연속 관측 N주 이상  AND  최근 지수가 바닥의 3배 이상
             (N 은 12~26 사이에서 백테스트로 정한다)
```

`keyword_registry` 가 `origin · discovered_at · first_observed_at · track` 을 들고 있으면
이 전이가 자동으로 굴러가고, 동시에 **"A 가 B 보다 몇 주 일찍 찾았나" 를 소급으로 잴 재료**가 쌓인다.

#### 비교 실험은 어떻게 되나

역할을 나누면 둘을 같은 지표 위에 올릴 수 없다. 원래의 중심 연구 질문
*"어느 경로가 더 일찍, 더 정확하게 찾는가"* 는 **Phase 1 범위에서 빠진다.**

다만 버리지는 않는다. 레지스트리에 발견 기록이 쌓이면 나중에 소급으로 복원할 수 있다 —
"B 가 결국 찾아낸 키워드들을 A 는 몇 주 먼저 언급했는가" 같은 형태로.
이것은 Phase 2 이후의 과제다.

> **대가를 분명히 해둔다.** 포트폴리오 관점에서 "두 방법을 겨루게 해 측정했다" 는 축이
> 당장은 빠진다. 대신 실제로 쓰이는 목록이 먼저 나온다. 목표를 A(주간 추천 목록)로
> 잡은 데 따른 선택이다.

## 3. 상류와 하류 — 신호의 지형

```
[상류] 동대문 도매 신상 → 신상마켓 업로드 (하루 3.5만 개)
          ↓ 2~4주
[중류] 셀러 사입 → 에이블리 등록 → 인스타/틱톡 노출
          ↓ 1~3주
[하류] 소비자 검색·클릭 → 쇼핑인사이트 · 검색어트렌드
```

| | 빠르기 | 정량화 | 노이즈 | 역할 |
|---|---|---|---|---|
| 상류 | ★★★ | ✗ | 많음 | 후보 발굴 |
| 중류 | ★★ | △ 수기 | 중간 | 확산 확인 |
| 하류 | ★ | ✓ API | 적음 | 검증·추세 |

**네이버는 하류다.** 소비자가 이미 알고 찾는 단계라 네이버에서 보이면 늦은 경우가 많다.
상류만 보면 오탐이 넘치고, 하류만 보면 늘 늦는다. 교차해야 한다.

## 4. 파이프라인

```
트랙 A ─ 신조어 ────────────────────────────────────────────────────┐
  LLM 웹 검색 ──► LLM 정규화 ──► 쇼핑인사이트 조회 ──► 관측률 판정    │
  패션 기사·콘텐츠   속성 분류      (대부분 결측)        "세기 시작했나"│
                                                            │        │
                                      졸업: 연속 관측 N주 ──┘        │
                                            ↓                        │
트랙 B ─ 기존 조합어 ─────────────────────────────────────────────┐  │
  검색광고 연관어 ──► LLM 정규화 ──► 쇼핑인사이트 조회 ──► 점유율 ──┤  │
  시드 → 연관어       속성 분류       10~20대 여성        ÷분야지수 │  │
  규모 필터           레지스트리 적재  주간 · 과거 백필             │  │
                                                                   │  │
                               패널 모형 / 규칙 탐지 ◄──────────────┘  │
                               상승률·가속도·지속성·놀라움             │
                                            │                         │
                                            ▼                         ▼
                        주간 리포트 — 세 칸 (주력 · 뜨는 것 · 꺾이는 것, §5-6)
                                   속성 단위 + 대표 검색어 병기
                                   신조어는 `신규` 꼬리표 · 확신도 낮춤
                                            │
                        플랫폼 랭킹 수기 기록 ◄┘
                        ↻ 정답지 — 다음 주 후보에 반영
```

### 단계별 책임

| 단계 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **발굴** | 후보 키워드 목록 생성 | **유행 판단** — 웹 기사는 공급측 의도일 뿐 |
| **정규화** | 속성 분류, 동의어 통합, 레지스트리 적재 | 중요도 가중 |
| **조회** | 세그먼트별 시계열 수집, 과거 백필 | - |
| **탐지** | 지표 계산, 점수화, 생애주기 분류 | - |
| **리포트** | 계산된 지표를 근거로 서술 | **숫자 창작** — 테이블 밖 수치 금지 |

> **LLM의 역할 경계**: LLM은 *분석 대상을 발굴하고 비정형 정보를 구조화*한다.
> 트렌드 **판정은 정량 모델이** 한다. LLM이 데이터를 보고 유행 여부를 판단하게 하지 않는다.

## 5. 트렌드 탐지 방법론

### 5-1. 지표

| 지표 | 정의 | 목적 |
|---|---|---|
| 최근 상승률 | 최근 4주 vs 이전 4주 | 성장 탐지 |
| 상승 가속도 | 증가 속도의 변화 (2차 차분) | 초기 급등 탐지 |
| 계절성 보정 상승률 | STL 분해 후 잔차 추세 / 전년 동기 대비 | 계절 반복과 구분 |
| 상승 지속성 | 최근 N주 중 양의 성장 주차 비율 | 일회성 급등 제외 |
| 관심도 수준 | 앵커 보정 상대지수의 분위 | 극소규모 변동 구분 |
| 신규성 | 장기 평균 대비 괴리, 최초 관측 후 경과 주차 | 신규 후보 구분 |
| **관측률** | 최근 N주 중 값이 온 주의 비율 | **트랙 A 전용 판정 지표** (§2-3). 결측이 줄어드는 것 자체가 신호 |
| 변화점 | 구조 변화 시점 탐지 | 추세 전환 포착 |
| 인구통계 스큐 | 10~20대 여성 비중 / 전체 비중 | 고객 적합성 |
| 교차 소스 확인 | 검색어트렌드·블로그 문서수와의 동반 상승 | 오탐 억제 |

### 5-2. 점수

```
T_i = w1·Z(growth_i) + w2·Z(acceleration_i) + w3·Z(persistence_i)
```

**가중치를 임의로 정한 점수를 최종 모델로 쓰지 않는다.**
과거 시점에서 추천한 뒤 실제로 이후 4~8주 상승했는지 백테스트해 가중치를 조정한다.

### 5-3. 생애주기 분류

| 상태 | 조건 | 사입 함의 |
|---|---|---|
| **Emerging** | 낮은 레벨 + 상승 시작 + 지속성 확인 | 소량 시험 사입 |
| **Growing** | 여러 기간 상승 확인 | 확대 후보 |
| **Mature** | 높은 레벨 + 증가세 둔화 | 유지, 신규 확대 자제 |
| **Declining** | 상대 관심도 감소 | **신규 사입 중단, 재고 소진** |

### 5-4. 오탐 억제 — 여기가 실제 난이도

연예인 착용 한 번으로 생긴 단발 스파이크와 진짜 트렌드를 구분해야 한다.

- **지속성 필터**: 3주 연속 양의 성장
- **신호 대 잡음비**: 상승폭 / 과거 변동성
- **다중 소스 동시 확인**: 쇼핑 클릭 + 검색 + 담론이 같이 움직이는가
- **괴리 신호 활용**: 검색은 느는데 쇼핑 클릭이 안 늘면
  → "화제성은 있으나 구매로 안 이어짐" → **사입 금지 신호**

### 5-5. 비용 비대칭

잘못 떼오면 재고 손실이 크고, 못 떼오면 기회손실인데 작다.
→ **정밀도 우선, 확신도 병기, 하락 경보를 상승 추천과 동등하게 취급.**

### 5-6. 주간 산출물 — 세 칸

**조기 탐지로만 좁히지 않는다.** 셀러가 한 회차에 떼오는 물량의 대부분은
가디건·청바지 같은 주력 품목이고 유행템은 일부다. 상승 후보 10개만 있는 종이는
실제 사입 회차의 작은 조각만 건드린다. 매주 열어보는 물건이 되려면
"늘 떼오는 것들은 지금 어떤가"가 같은 장에 있어야 한다.

다만 **규모순 전체 랭킹은 내지 않는다.** 검색량 큰 순으로 줄 세우면 1등은 늘 원피스,
2등은 늘 청바지다. 셀러가 이미 아는 것이고 모형도 필요 없다. 정보가 아니라 소음이다.

| 칸 | 모집단 | 보여주는 것 | 비고 |
|---|---|---|---|
| **주력** | 시드 31개 — 발굴 24 + 관찰 7 (= `config/keywords.yaml`) | 평년 곡선 대비 현재 위치, 품목 안 구성 변화 | 추가 수집 없음 — 이미 매주 받고 있다 |
| **뜨는 것** | 발굴 후보 (트랙 A·B) | 점유율 상승률·가속도·지속성 상위 10 | **§5-1~5-4 가 다루는 본체** |
| **꺾이는 것** | 시드 + 과거 추천 이력 | 하락 전환 품목 — 신규 사입 중단·재고 소진 | §5-3 `Declining` |

가운데 칸이 이 프로젝트의 기여고, 위아래는 그 판단을 놓을 맥락이다.
설계는 이미 반쯤 넓어져 있었다 — 하락 경보(§5-5)는 처음부터 주력 품목 얘기였다.

#### 주력 칸에 무엇을 쓰는가

전년 동기 대비 한 줄로는 부족하다. 주력 품목은 2017년부터 주간 데이터가 쌓여 있어
할 수 있는 게 더 많고, **전년 대비는 그중 가장 약하다** — 기준이 작년 한 해뿐이라
작년이 이상했으면 비교 자체가 틀린다. 실제로 그렇다: 패션 카테고리가 1년 만에
43.5% 빠졌다(§4 플랫폼 드리프트). 작년 숫자는 기준으로 못 쓴다.

| | 지표 | 어떻게 | 사입 함의 |
|---|---|---|---|
| ① | **품목 안 구성 변화** | 해당 시드를 포함한 조합 키워드들의 점유율 분포 변화 (`버건디 가디건` / `가디건` 등) | **가장 강하다.** "가디건은 작년만큼 떼되 색 구성을 바꿔라" |
| ② | **계절 곡선 위 현재 위치** | 과거 N년 주간 점유율의 주차별 중앙값 = 평년 곡선. 현재 주차의 구간(상승/정점/하강)과 피크까지 남은 주수 | 발주 타이밍. **올해가 평년보다 빠른지 늦는지**가 더 유용 — 따뜻한 가을이면 코트가 2~3주 밀린다 |
| ③ | **평년 대비 편차** | 현재 점유율 ÷ 평년 곡선의 해당 주차 값 | 전년 대비를 대체한다. 기준이 1년이 아니라 N년 |
| ④ | **세그먼트 이동** | 쇼핑인사이트 성별·연령 분해 (§1-1) | 수요가 평평해도 10대→20대 후반으로 옮겨가는 중이면 톤을 바꿔야 한다 |

②~③은 §5-1의 "계절성 보정 상승률"과 같은 재료를 쓴다. 다른 점은 **출력 형태**다 —
탐지는 잔차의 부호를 보고, 주력 칸은 곡선 위 위치와 편차를 그대로 보여준다.

①은 §7-2 속성 집계(`{axis}_glevel` 등)와 같은 groupby에서 나온다. 추가 수집이 없다.

> **한계를 칸에 적는다.** 네이버는 수요(관심)만 보여준다. 공급·가격·동대문 재고 상황은
> 모른다. 검색은 구매가 아니다. 판매 데이터가 들어오기 전까지 주력 칸의 문구는
> "이만큼 팔린다"가 아니라 **"평년 이 주차 대비 관심이 이렇다"** 로 고정한다.

> **주력 칸의 "가디건"은 시드 단독 시계열이 아니다.** 2026-10-27 실측으로 네이버
> 키워드 매칭이 완전일치임이 확인됐다(§7-0). `가디건` 한 건만 조회하면 실제 가디건
> 수요의 10분의 1만 보게 된다 — `여성가디건` 하나가 `가디건` 보다 크다.
>
> ```
> 품목 시계열(가디건, t) = Σ  share(k, t)     k ∈ 관측된 '…가디건' 키워드
> ```
>
> 평년 곡선도 편차도 이 합산 시계열 위에서 만든다. 합산 모집단이 주마다 달라지면
> 추이가 오염되므로 **키워드 집합을 고정한 뒤 과거를 백필**한다(§2-2).
> 모집단에 무엇을 넣고 뺄지는 `exclude_patterns` 가 결정한다 — 실측에서 `남자가디건`
> 31,630 · `남성가디건` 8,840 이 잡혔다. 거르지 않으면 품목 시계열의 상당 부분이
> 타깃 밖 수요다.

## 6. 평가 설계

### 6-1. 탐지 성능 (판매 데이터 없이도 측정 가능)

| 지표 | 확인하려는 것 |
|---|---|
| **Precision@10** | 추천 상위 10개 중 이후 4~8주 실제 상승한 비율 |
| **Recall@K** | 사후 확인된 상승 트렌드를 얼마나 찾아냈나 |
| **Lead Time** | 상승이 뚜렷해지기 몇 주 전에 탐지했나 (중앙값) |
| **False Alarm Rate** | 상승 예측했으나 실제로는 아니었던 비율 |
| **하락 경보 적중률** | 악성재고 회피 기여 |

- 롤링 오리진 교차검증, 최소 3폴드, 폴드 간 gap = 평가 지평 (누수 차단)
- 베이스라인: (a) 단순 상승률 정렬 (b) 레벨 상위 정렬 (c) 랜덤
- 베이스라인에 **계절 나이브**(작년 같은 주)를 반드시 포함 — 계절성만으로 설명되는 상승을 걸러낸다
- **규칙 vs 패널 모형**을 같은 지표로 비교. 모형이 규칙을 못 이기면 쓰지 않는다
- 경로 A vs B 비교는 Phase 1 범위 밖이다 (§2-3). 레지스트리에 기록만 쌓아 둔다

> 이것은 **미래 쇼핑 클릭 관심도 예측 성능**의 검증이다.
> 판매량 예측이나 수익 개선을 검증하는 것이 아니다. 리포트에 이 한계를 명시한다.

### 6-2. 앵커 보정 타당성 검증

> 2026-10-22 개정. 1번은 끝났고, 남은 것은 2·3번이다. 배경은 §2-1.

**1. 스케일 정합 — 완료, 검증 불필요**

같은 요청 / 따로 조회 후 앵커 보정의 상대오차가 26주 전 구간 0.0%였다.
약분이 항등식이므로 앵커를 바꿔도 결과는 같다. **앵커 후보 비교는 의미가 없다.**
구현 시 같은 검산(같은 요청 / 따로 조회 후 앵커 보정)을 테스트로 한 번 넣어 두면
회귀 방지로 충분하다.

**2. 규모대 사다리의 해상도 — 검증 대상**

단일 앵커에서 소규모 키워드가 `0.00437` 바닥에 눌리는 것을 확인했다.
규모별 사다리가 이걸 실제로 회복시키는지 재야 한다.

- 같은 소규모 키워드를 ① 대형 앵커와 함께, ② 소형 대역 안에서 조회
- 유효숫자 자릿수와 주간 변화의 분산을 비교 — 대역 안에서 변동이 살아나야 한다
- 중간 앵커가 두 대역 모두에서 안 눌리는 크기인지 확인
- 사다리 단수를 늘렸을 때 수치가 흔들리지 않는지(항등식대로 0이어야 한다) 확인

**3. 결측 처리 규칙 — 검증 대상**

네이버가 보내지 않은 구간을 어떻게 다루느냐가 지표를 바꾼다.

- 0 대입 / 결측 유지 / 보간 세 가지로 같은 키워드의 상승률·가속도·지속성을 계산해 비교
- 규모대를 바꿔 조회하면 같은 구간이 돌아오는지 — 결측이 **절대 검색량** 때문인지
  **배치 내 상대 크기** 때문인지 가른다. 후자라면 사다리로 결측 자체가 줄어든다
- 결측률 감소가 신생 트렌드의 선행 신호가 되는지 소급 백테스트로 측정

> **LLM 을 수집 앞에 둔다** (2026-10-28 변경). 원안은 수집 뒤였는데, 그러면
> 버릴 키워드의 시계열까지 다 받고 나서 버린다. 쇼핑인사이트 호출이 이 파이프라인에서
> 제일 비싼 자원인데 6할을 낭비하는 셈이다.
>
> LLM 판정에는 시계열이 필요 없다 — **키워드 문자열만** 있으면 패션 여부도 속성 분해도 된다.
> 앞으로 옮기면 호출이 줄 뿐 아니라, **버릴 키워드가 앵커 배치의 4칸을 차지하지 않는다.**
>
> 대가: `LLM_MODE=stub` 상태에서는 2·3 이 규칙 기반 폴백이라 선별이 거칠다.
> Anthropic 키가 없으면 수집량이 덜 준다 — 작업 순서에서 LLM 단계를 앞당겨야 하는 이유다.

**조회하는 것과 계산하는 것을 구분한다.** 이것을 헷갈리면 조합 폭발이 일어난다.

| | 대상 | 비용 |
|---|---|---|
| **조회** | LLM 선별을 통과한 검색어 — 격자 노드 약 1,700개 | API 286회 |
| **계산** | 속성군 시계열 · 시차 · 집계 · 타깃 | API 0회 (pandas) |

`"버건디"` 를 조회하는 일은 없다. 버건디가 붙은 키워드들을 **더해서** 버건디군 시계열을 만든다.
`"버건디"` 단독 검색은 와인·립스틱·염색약이 섞여 옷 수요를 대변하지 못한다.
마찬가지로 `색상 × 품목` 조합을 생성해 조회하지 않는다 — 연관어에 뜬 것만 추적하고,
조합은 `groupby` 로 접는다.

> **2026-10-27 실측 — 네이버 키워드 매칭은 완전일치다.** 상위어가 하위 조합어를 품지 않는다.
>
> ```
> 검색광고   '가디건' 38,750  vs  '…가디건' 440개 합 354,980   (자체는 11%)
>            '여성가디건' 44,160 > '가디건' 38,750             ← 자식이 부모보다 크다
> 쇼핑인사이트 가디건 vs 자식 4개, 52주 중 53/53 주에서 자식합 > 부모
> ```
>
> 따라서 **시드 단독 시계열은 그 품목의 시장이 아니다.** `가디건` 은 "가디건이라고
> 정확히 친 사람"일 뿐이고, 품목 전체를 보려면 `…가디건` 으로 끝나는 관측 키워드를
> 전부 더해야 한다. 위 문단의 "더해서 만든다"는 방침이 선택이 아니라 **필수**가 된 셈이다.
> 상위·하위 관계를 특징으로 쓰는 방법은 [MODEL.md](MODEL.md) 의 격자 절에 정리했다.

월 1만 이상은 범용어 오염 구간이다(관련도 9%).

### 7-2. `panel` — 모형이 먹는 표

행은 `(keyword, period)`. **LLM 선별 뒤** 격자 노드 약 1,700개 × 480주 ≈ **82만 행**,
열 80개 안팎. float32 로 262MB — 노트북에서 돌아가지만 pandas float64 통째로는 520MB 다.
**parquet + float32 + 필요한 열만** 읽는다. 최근 3년으로 자르면 27만 행(86MB).

> 선별 전 리프가 ~3,350 이고 관련도가 41%(발견 ⑩)이므로 1,400 안팎이 남는다는 계산이다.
> **시드당 상한은 품질 장치로 쓰지 않는다** — 규모 상위를 자르면 관련도가 **더 높은** 쪽을
> 버리게 된다(⑩은 규모와 관련도가 반비례). 폭주 방지용으로 **시드당 300** 만 둔다.
저장 테이블이 아니라 위 테이블들에서 **파생**한다.

| 묶음 | 열 | 설명 |
|---|---|---|
| 키 | `keyword` · `period` | |
| 값 | `share` | §7-0 3단계 결과. 모든 계산의 바탕 |
| **타깃** | `y = log( mean(share, t+1…t+4) / mean(share, t-3…t) )` | **4주 평균끼리의 로그 비.** 수준이 아니라 변화율. 점 대 점이 아닌 이유는 [MODEL §4-5](MODEL.md) |
| 자기 과거 | `lag_1 · 2 · 4 · 8 · 13 · 26 · 52` | 52주 = 작년 같은 주 |
| | `growth_4v4` · `accel` · `persistence_4w` | |
| | `roll_mean_8` · `roll_std_8` | 변동성 |
| 관측 상태 | `obs_rate_8w` | 최근 8주 중 값이 온 비율 — 트랙 A 신호 (§2-3) |
| | `weeks_since_first_obs` · `at_floor` | |
| 달력 | `woy_sin` · `woy_cos` | 연중 주차를 원형으로 |
| 속성(범주) | `item` · `color` · `material` · `fit` · `length` · `silhouette` · `pattern` · `detail` · `style` · `occasion` · `season` · `era` | LightGBM 범주형. 대부분 null |
| 속성(집계) | `{axis}_gn` · `{axis}_glevel` · `{axis}_ggrowth` | **12축 × 3 = 36열.** leave-one-out |
| **격자** | `depth` · `n_mod` · `parent_*`(`_growth`·`_level`·`_n`·`_lag52`) · `sibling_*` · `item_group_*` | 키워드 격자 특징 → [MODEL.md §3-x](MODEL.md). cold start 를 여기서 푼다 |

| 교차 소스 | `search_share` · `divergence` | 검색 − 클릭 증감률 차 (§5-4) |

#### 속성 집계 세 개가 각각 하는 일

버건디가 붙은 키워드가 4개이고 4주 전 합이 0.043, 지금 합이 0.064라면

```
color_gn       = 4         그 군에 키워드가 몇 개인가      → 신뢰도
color_glevel   = 0.064     그 군이 지금 얼마나 큰가        → 큰 색인가 작은 색인가
color_ggrowth  = +48.8%    그 군이 4주간 얼마나 컸는가     → 뜨는 중인가
```

버건디가디건 행에 붙일 때는 **자기를 뺀다.** 군이 작을수록 차이가 크다 —
3개짜리 군에서는 자기가 군 평균의 3분의 1이라 사실상 답을 훔쳐보게 된다.

```python
g   = panel.groupby(["color", "period"])["g4"]
loo = (g.transform("sum") - panel["g4"]) / (g.transform("count") - 1)
```

#### 타깃을 변화율로 두는 이유

키워드 간 수준 차이가 수십 배다 (트위드자켓 0.43 vs 버건디가디건 0.012).
`share` 를 그대로 타깃으로 두면 모형이 **크기 맞히기에 힘을 다 쓰고 변화를 놓친다.**
손실함수도 큰 키워드에 지배당한다.

```
            share(t)  share(t+4)   y = log 비
트위드자켓     0.4258     0.5110    +0.182
버건디가디건   0.0117     0.0140    +0.179    ← 크기는 36배, y 는 거의 같다
```

수준 변수(`share` · `glevel` · `monthly_volume`)는 버리지 않고 **조건**으로 남긴다.
같은 +20% 라도 큰 키워드와 작은 키워드에서 의미가 다르기 때문이다. 로그를 씌워 넣는다.

예측값은 되돌려 쓴다.

```
예상 share(t+4) = share(t) × exp(ŷ)
놀라움          = 실제 y − 예측 ŷ        ← 탐지 신호
추천 순위       = ŷ 내림차순             ← 되돌릴 필요도 없다
```

#### 학습/평가 분할

롤링 오리진. **폴드 사이에 타깃 지평만큼(4주) 공백**을 둔다.

```
[─── 학습 ───][4주 공백][평가]
       [─── 학습 ───][4주 공백][평가]
              [─── 학습 ───][4주 공백][평가]
```

공백이 없으면 학습 구간 마지막 행의 타깃이 평가 구간에 걸쳐 샌다.

#### 구축할 때 지킬 일곱 가지

```
1  한 수집 회차의 모든 배치는 기간이 같아야 한다   (앵커 평균의 의미가 깨진다)
2  앵커가 빠진 배치는 버린다                      (이어붙일 기준이 없다)
3  결측은 0으로 안 채운다                         (0 은 "급등"을 조작한다)
3a 백필 안 끝난 구간엔 행을 만들지 않는다           (우리 공백을 데이터로 착각한다 — MODEL §4-2)
3b 군 집계는 균형 패널로 비교한다                  (멤버 복귀가 "급등"으로 읽힌다 — MODEL §4-3)
4  속성 집계는 자기를 뺀다                         (leave-one-out)
5  모든 특징은 t 시점까지만 본다                   (속성 집계도 마찬가지)
6  y 는 4주 평균끼리의 로그 비                     (점 대 점은 검열 한 주에 죽는다)
7  at_floor 행은 학습에서 빼거나 가중치를 낮춘다    (한 칸 올라간 게 +100% 로 보인다)
```

#### 만드는 순서

```
분야지수 → 원시수집 → 환산 → panel 뼈대(속성 없이) → 백테스트 틀 → 베이스라인
                                                           ↓
                                              속성 라벨 → 속성 집계 → 모형
```

**속성을 가장 늦게 붙인다.** 속성 없는 패널로 먼저 베이스라인을 잡아두면,
속성을 넣었을 때 얼마나 좋아졌는지가 바로 숫자로 나온다.

### 7-3. 이 표 위에서 무엇을 추정하는가

모형 쪽은 분량이 커져 따로 뺐다 → **[MODEL.md](MODEL.md)**.

- 왜 키워드별 ARIMA 가 아니라 패널인가 (조기 탐지 대상이 바로 과거가 짧은 키워드다)
- 왜 키워드 고정효과를 안 쓰는가 (신규 키워드에 넣을 값이 없다 → 속성이 대신한다)
- M0 계절 나이브 → M1 규칙 → **M2 패널 선형 AR** → M3 LightGBM 사다리와 수용 기준
- 자기회귀 항의 시차 집합과 그 근거, 계절을 Fourier 와 시차 52 로 이중으로 두는 이유
- 결측이 있는 시차를 M2 와 M3 에서 다르게 다루는 법, 그리고 비교 시 표본 맞추기
- 예측(`ŷ`, 추천용)과 놀라움(`y − ŷ`, 4주 지연 감시용)의 분리

## 8. 범위 — 단계별

### Phase 0 — 확인 (코드 없음)
- 네이버클라우드 가입 → API HUB 쇼핑인사이트 키
- 네이버 검색광고 계정 → 키워드도구 API 라이선스
- 친구: [CLIENT.md](CLIENT.md) 부록의 판매자센터 항목 확인
- 친구: 과거 사입 이력 (터진 것 5~10개 / 죽은 것 5~10개, 품목·시점·이유)

### Phase 1 — 조기 탐지 ★본체
1. 쇼핑인사이트 연결, 여성 패션 기본 품목 20~30개로 응답 형식·조회 범위 확인
2. 앵커 체이닝 구현 + 타당성 검증 (§6-2)
3. 점유율 전환 — 분야 지수 수집 후 키워드 지수를 나눈다 (§4 플랫폼 드리프트)
4. 트랙 B 구현 — 시드 → 검색광고 연관어 → 규모 필터(월 100~1만). **실측 ~3,350개**
   (힌트 1개씩 단독 조회. 5개씩 묶으면 응답 한도를 나눠 써 뒤쪽이 잘린다)
5. LLM 정규화 — 패션 여부 판정, 속성 분류, 동의어 통합, 레지스트리 적재, 과거 백필
6. 탐지 — 점유율 기준 상승률·가속도·지속성, 계절성 보정, 괴리 신호
7. 트랙 A 구현 — LLM 웹검색 발굴 + 관측률 판정 + 졸업 규칙 (§2-3)
8. 백테스트 — 가중치 조정, 졸업 기준 N 결정
9. 주력 칸 — 평년 곡선 산출, 편차·피크 잔여주수·구성 변화 (§5-6)
10. 주간 리포트 + Streamlit 대시보드

**1차 산출물**: *매주 한 장. 주력 · 뜨는 것 · 꺾이는 것 세 칸* (§5-6)
가운데 칸이 본체다 — 스타일 TOP 10, 각각 상승 근거, 지난 1년 관심도 변화,
계절성, 불확실성, 관련 검색어. **하락 경보를 동등한 비중으로 함께 낸다.**

> 9번은 8번 뒤에 둔다. 평년 곡선은 탐지의 계절성 보정과 같은 재료를 쓰므로,
> 보정이 백테스트로 검증된 뒤에 꺼내 보이는 편이 안전하다.

> **사입 수량은 넣지 않는다.** 판매·원가·재고 없이 산출한 수량은 전부 가정 위의 숫자라
> 오히려 신뢰를 깎아먹는다. 수량은 Phase 3.

### Phase 2 — 속성 레이어
키워드 지수를 속성 지수로 집계. "원피스가 뜬다"가 아니라 "벌룬 실루엣 + 새틴이 뜬다" 수준.
멀티모달 확장(상품 사진 → 색상·실루엣·디테일)은 여기서 검토.

### Phase 3 — 캘리브레이션 + 사입 최적화 *(판매 데이터 확보 시에만)*
검색지수 → 실판매 전이모델, 속성별 선행 주차, 예산 제약하 사입 수량 최적화.
상관이 낮은 속성은 신호에서 제외.

## 9. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **네이버 신호 ≠ 에이블리 고객** | 시스템 전체 무용화 | 세그먼트 필터 고정, 수기 랭킹으로 간극 측정, 상관 낮은 속성 제외 |
| 판매 데이터 확보 실패 | Phase 3 불가 | Phase 1~2만으로도 포트폴리오 성립. 과거 사입 이력으로 사후 검증 |
| 소규모 키워드 해상도 소실 | 조기 탐지가 노리는 신생 키워드를 못 봄 | 규모대별 앵커 사다리(§2-1). 바닥(`0.00437`)에 닿은 키워드는 추정 불가로 표기 |
| 결측 구간 처리 오류 | 급등·지속성 지표 왜곡 | 0으로 메우지 않는다. 규칙을 §6-2에서 비교 검증 |
| 오탐 과다 | 재고 손실, 신뢰 상실 | §5-4 필터, 정밀도 우선, 확신도 병기 |
| LLM 웹검색의 공급측 편향 | 유행하지 않을 것을 추천 | 후보 발굴에만 사용, 판단 근거로 금지 |
| 친구가 안 쓴다 | 사업 검증 실패 | 포트폴리오 목표는 독립적으로 달성 (§0) |

## 10. 기술 스택

| 영역 | 기술 |
|---|---|
| 수집 | Python, httpx, tenacity (재시도·레이트리밋) |
| 저장 | SQLite (단일 사용자 규모에 충분, 필요 시 DuckDB) |
| 분석 | pandas, numpy, statsmodels (STL·변화점), scikit-learn |
| LLM | Anthropic API (발굴·정규화·리포트), 디스크 캐시로 중복 호출 차단 |
| 프론트 | Streamlit |
| 운영 | 주간 스케줄러, 로그, 실패 알림 |

### 키 없이도 돌아간다
`SOURCE_MODE=mock` — 계절성·추세·신규 트렌드 등장을 포함한 합성 데이터 생성기.
`LLM_MODE=stub` — 규칙 기반 폴백 (taxonomy의 aliases 사용).
키 0개로 수집→탐지→리포트 end-to-end 검증이 가능하다.
