| | 발견 | 영향 |
|---|---|---|
| ① | 엔드포인트 4개 확인. 404/401 로 생사 판별 | 이관 후 경로 확정 |
| ② | `ratio` 분모는 **요청 전체에 하나** (키워드×기간 통틀어 최댓값) | 앵커 체이닝이 근사가 아니라 **항등식**. 실측 오차 0.0% |
| ③ | 양자화 바닥 `0.00437` | 소규모 키워드 지표 신뢰 불가 → 규모대별 앵커 사다리 필요 |
| ④ | 네이버가 결측 구간을 **응답에서 생략** | 0으로 메우면 안 됨. 결측률 자체가 신규성 신호일 수 있음 |

| ⑦ | 띄어쓰기·대소문자 무시, **맞춤법 변형은 별개** (자켓:재킷 ≈ 200:1) | 표기 변형을 따로 조회해 합산해야 함 |
| ⑧ | 쇼핑인사이트 `param` 은 1개만 (구 데이터랩과 다름) | 변형 합산을 API가 안 해줌 |

## 결정한 것

- **목표는 A — 주간 추천 목록.** 친구에게 매주 보여주는 것을 1차 산출물로 삼는다
- **후보 모집단은 시드 + 검색광고 연관어.** LLM 웹검색(경로 A)은 나중
- **거르기는 LLM이 한다.** 단어 매칭 필터는 임시방편
- **분석 단위는 속성 + 검색어 병기.** 속성으로 신호를 얻고 검색어로 행동을 보여준다
- **LLM에게 유행 여부를 묻지 않는다.** 분류·정규화까지만. 판정은 정량 모델
- 모형을 쓴다면 **키워드별이 아니라 패널(전역) 모형.** 속성값을 입력 변수로
- **두 발굴 경로는 겨루지 않고 일을 나눈다** (ARCHITECTURE §2-3 개정)

```
트랙 A  신조어       LLM 웹검색 발굴 → 관측률로 판정 ("네이버가 세기 시작했나")
트랙 B  기존 조합어   연관어 발굴    → 점유율 상승률·가속도·지속성으로 판정
                     졸업: 연속 관측 N주 이상이면 A → B
```

- 속성은 **값을 열로 만들지 않는다.** 축 11개는 고정, 값은 그 값의 집계 통계로
  치환한다(`color_growth` · `color_n` 등). 새 색이 생겨도 입력 모양이 안 바뀐다
- 조합을 생성해 조회하지 않는다. **실재하는 키워드만 수집**하고 속성 집계는 groupby 로 만든다
- **타깃은 수준이 아니라 변화율** — `y = log(4주평균 비)`. 키워드 간 수준이
  수십 배 차이라 `share` 를 그대로 맞히면 크기 맞히기에 힘을 다 쓴다
- 모형 데이터 구축 절차와 `panel` 명세는 ARCHITECTURE §7 에 정리했다

### 2026-10-27 추가

- **타깃을 점 대 점에서 4주 평균 비로 바꿨다.** `log(s(t+4)/s(t))` 는 기준점 한 주가
  검열되면 라벨이 통째로 없어지고, 검열이 아니어도 계단(고유값비 0.45) 위의 한 점이라
  불안정했다. 양쪽을 4주 평균으로 두면 검열 주를 바닥값으로 채워도 지배력이 없고,
  분자·분모에 같은 규칙을 써서 편향이 상쇄된다 (MODEL §4-5)

- **산출물 범위를 넓혔다.** 조기 탐지 TOP 10 한 덩어리 → **세 칸**(주력 · 뜨는 것 · 꺾이는 것).
  사입 회차 물량의 대부분이 주력 품목이라 상승 후보만으로는 매주 열어볼 물건이 안 된다.
  가운데 칸이 여전히 본체고, 위아래는 맥락이다 (ARCHITECTURE §5-6)
- **규모순 전체 랭킹은 안 낸다.** 1등은 늘 원피스다. 셀러가 이미 아는 것이고 정보가 아니다
- **주력 칸은 전년 대비로 쓰지 않는다.** 기준이 작년 한 해뿐인데 그 작년이 −43.5% 였다.
  대신 네 가지 — ①품목 안 구성 변화(가장 강함) ②평년 곡선 위 현재 위치·피크 잔여주수
  ③평년 대비 편차 ④세그먼트 이동. 넷 다 추가 수집 없이 기존 재료로 나온다
- **주력 칸 문구는 "관심"으로 고정.** 네이버는 수요만 보여주고 공급·가격은 모른다.
  판매 데이터 전까지 "이만큼 팔린다"로 쓰지 않는다

- **시드를 전면 개정했다** (`config/keywords.yaml`). 26개 → **발굴 24 + 관찰 7**.
  역할을 나눈 이유는 수확 0인 시드를 발굴에 넣어봐야 호출만 쓰고 격자가 안 생겨서다.
  신규 8개(조끼·바지·스커트·팬츠·반바지·나시·집업·점퍼), 제외 3개(셋업·크롭티·베스트)
- **시드당 상한은 품질 장치로 쓰지 않는다.** 규모 상위를 자르면 관련도가 더 높은 쪽을
  버린다(발견 ⑩). 실제 선별은 LLM 이 하고, 상한 300은 폭주 방지용일 뿐이다
- **LLM 을 수집 앞으로 옮겼다** (ARCHITECTURE §7-0). 원안은 수집 뒤라 버릴 키워드의
  시계열까지 받고 나서 버렸다. 판정에 시계열이 필요 없으므로 앞에 두면 호출이 4할 줄고,
  버릴 키워드가 앵커 배치의 4칸을 차지하지 않는다

- **v0 프로파일을 뒀다** — 1차 구현은 **발굴 시드 20개**(여름 품목 나시·반바지,
  수확 낮은 점퍼·무스탕 제외)에 **월 400~4,000 · 시드당 30개**. 리프 ~600 · 35만 행.
  시드를 줄여도 규모는 8%밖에 안 준다(3,350→3,088) — 레버는 **시드당 후보 수**다.
  대역을 좁히는 이유는 월 400 이상에서 관측률 1.00 · 고유값비 0.80 이라
  **결측·양자화 대응 없이도 파이프라인이 돈다**는 것 (MODEL §4-0)

### 다음 작업 순서 (v3 — 모형까지)

시드는 친구 답을 기다리되, **모형 실험은 지금 시드 32개로 바로 시작할 수 있다.**
실험 목적이 "계절성·관성을 제거하면 더 일찍 찾는가" 라서 시드가 무엇이든 성립한다.

> **중간에 뒤집은 판단**이다. 현행 설계는 언제나 ARCHITECTURE 가 우선한다.

## 정정 이력

정직하게 남겨둔다. 틀렸던 것과 왜 틀렸는지가 설계의 일부다.

### 1. "수기 관찰을 최우선으로" → **철회**

**처음 주장**: 시계열은 지나간 주를 되돌려 수집할 수 없으니 오늘부터 쌓아야 한다.

**왜 틀렸나**: 쇼핑인사이트가 2017-08-01까지 소급 조회된다는 걸 과소평가했다.
과거 시점으로 돌아가 백테스트하면 **오늘 당장** 모델을 검증할 수 있다. 8주를 기다릴 필요가 없다.

**지금**: 수기 관찰은 유지하되 2순위. 역할도 바뀌었다 — 모델 검증용이 아니라
"검색 관심도 ≠ 에이블리 실판매" 간극을 메우는 보완재.
*(단 플랫폼 랭킹은 API가 없어 소급이 불가능하므로, 그 용도로는 여전히 지금부터 쌓아야 한다.)*

### 2. 호출 한도 "하루 1,000회" → **월 50,000회**

구 데이터랩 문서 기준의 수치였다. API HUB 기준은 월 50,000건 / 50 RPS.
수집 예산이 훨씬 넉넉해서 세그먼트를 나눠 돌릴 여유가 생겼다.

### 3. 초기 설계의 과잉 → **범위 축소**

처음엔 LightGBM 글로벌 모델, 분위 회귀, 다계층 앙상블까지 설계했다.
판매 데이터가 없는 단계에서는 전부 쓸 데가 없다. Phase 3으로 미뤘다.

**1차 산출물에 사입 수량을 넣지 않기로 했다.** 판매·원가·재고 없이 산출한 수량은
전부 가정 위의 숫자라 오히려 신뢰를 깎아먹는다.

### 4. "두 발굴 경로를 경쟁시킨다" → **역할 분담으로 교체** *(10-22)*

**처음 주장**: LLM 웹검색 경로와 검색광고 연관어 경로를 같은 지표 위에 올려
승부를 낸다. 이게 프로젝트의 중심 연구 질문이다 (§3-3).

**왜 틀렸나**: 둘은 같은 종류의 키워드를 집지 않는다. LLM 웹검색이 가져오는 것은
**과거 데이터가 거의 없는 신조어**고, 연관어가 가져오는 것은 **이미 관측 이력이 있는
조합어**다. 전자는 시계열이 없어 상승률·가속도를 계산할 수 없으므로 애초에
Precision@10 을 매길 수 없다. 공정한 비교가 성립하지 않는다.

**지금**: 트랙 A(신조어)는 **관측률**로 판정하고 — 네이버가 그 말을 세기 시작했는가 —
연속 관측 N주를 넘기면 트랙 B로 **졸업**한다. 트랙 B(조합어)는 점유율 상승률·가속도·
지속성으로 판정한다. 비교 실험은 레지스트리에 발견 시점만 쌓아 두고 Phase 2 이후로 미뤘다.

**중심 질문은 이렇게 바뀌었다** — *계절성과 관성을 걷어낸 뒤에도 남는 상승 신호가,
단순 규칙보다 더 일찍·더 정확하게 사입할 만한 품목을 집어내는가?*
비교 대상은 다른 발굴 경로가 아니라 **계절 나이브**와 **단순 상승률 규칙**이다.

### 5. "조기 탐지만 낸다" → **세 칸으로 확대** *(10-27)*

**처음 주장**: 1차 산출물은 상승 후보 TOP 10. 이미 뜬 것을 보여주는 건 늦으므로
조기 탐지에만 집중한다.

**왜 좁았나**: 셀러가 한 회차에 떼오는 물량의 대부분은 가디건·청바지 같은
주력 품목이고 유행템은 일부다. 상승 후보 10개만 있는 종이는 실제 사입 회차의
작은 조각만 건드린다. 게다가 **하락 경보는 처음부터 주력 품목 얘기였다** —
설계는 이미 반쯤 넓어져 있었는데 이름만 "조기 탐지"로 좁혀 부르고 있었다.

**지금**: 주력 · 뜨는 것 · 꺾이는 것 **세 칸**. 가운데가 본체고 위아래는 맥락이다.
다만 **규모순 전체 랭킹은 내지 않는다** — 1등은 늘 원피스고, 셀러가 이미 아는 것은
정보가 아니다. 주력 칸은 전년 대비가 아니라 평년 곡선 대비로 쓴다
(기준이 작년 한 해뿐인데 그 작년이 −43.5% 였다). 상세는 [ARCHITECTURE §5-6](ARCHITECTURE.md).

## 반복해서 확인된 원칙들

**LLM은 발굴하고 구조화한다. 판정은 정량 모델이 한다.**
LLM이 데이터를 보고 "이게 유행이다"라고 판단하게 두지 않는다.
리포트 단계의 LLM도 계산된 지표를 근거로 서술만 하고, 테이블 밖 숫자를 만들지 않는다.

**웹 기사는 공급측 의도다.**
매거진이 "올해는 버건디"라고 쓰는 건 브랜드가 밀기로 한 것이지
10대가 사고 있다는 뜻이 아니다. 웹 검색 결과는 **후보 발굴에만** 쓰고 판단 근거로 쓰지 않는다.

**계절성을 못 빼면 시스템이 평생 "겨울엔 패딩"만 말한다.**
STL로 계절 성분을 제거한 잔차가 진짜 신호다. 패션에선 이게 작업의 절반쯤 된다.

**검색과 쇼핑 클릭의 괴리가 정보다.**
검색은 느는데 쇼핑 클릭이 안 늘면 "화제성은 있으나 구매로 안 이어짐" = **사입 금지 신호**.

**세그먼트 필터는 선택이 아니라 기본값이다.**
타깃이 10~20대 여성인데 전체로 조회하면 40~50대 구매력에 묻힌다.

## 가장 큰 미해결 리스크

**네이버 신호가 에이블리 고객을 대변하는가?**

10~20대 여성은 탐색을 네이버가 아니라 에이블리 앱·인스타·틱톡에서 한다.
네이버 지수가 올라도 에이블리에서는 이미 늦었거나 아예 안 올 수도 있다.

대응은 세 가지이고, 셋 다 **검증이 필요한 가설**이지 해결책이 아니다:

1. 세그먼트 필터로 네이버 안에서 같은 인구집단을 뽑아낸다
2. 친구의 파트너센터 통계를 정답지로 삼는다 (확보 가능한 경우)
3. 속성별로 상관을 측정해 상관 낮은 속성은 신호에서 제외한다

이 리스크가 해소되지 않으면 시스템은 "참고용 신호"에 머문다.
해소되면 "사입 결정 도구"가 된다. 차이가 크다.
